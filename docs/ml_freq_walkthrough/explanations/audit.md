## @module  [9fab8be6]
Команда `audit` отвечает на вопрос «каким данным можно верить». Склеенная статистика 2021–2026 содержит блоки, сдвинутые на 180 дней, а в разметке технологов есть мероприятия, которых замеры не подтверждают. Модуль берёт результат `MergedWellRepository.build()` (скважины + `DataAudit` с решениями) и делает из него три вещи:

1. Текстовый отчёт в консоль (`DataAuditReport.to_text`).
2. Файлы в `results/ml_freq/data_audit/`: `data_audit.xlsx`, `data_audit.png`, `rejected_labels.csv` (`DataAuditReport`).
3. Файл `training_data.xlsx` — ровно те данные, на которых учатся модели (`TrainingDataReport`).

Сам алгоритм исправления сдвигов находится в `data/repair.py` (`BlockShiftRepair`), отбор мероприятий — в `data/dataset.py`. Здесь только отчётность и командная строка (`build_parser`, `run`, `main`). Длинная документация в начале файла объясняет, откуда берётся сдвиг и как принимаются решения «без сдвига», «сдвиг −180 дн», «исключён».

Запуск:

```bash
.venv/Scripts/python -m gtm_detector.ml_freq audit
.venv/Scripts/python -m gtm_detector.ml_freq audit --out-dir results/ml_freq/debug/audit --no-reference
```

Первое чтение Excel занимает около 30 секунд.

### Цифры последнего запуска (merged)
- Из 786 строк разметки принято 135 мероприятий на 122 скважинах; отброшено 333 «скважины нет в статистике», 153 «нет замеров около даты начала», 89 «частота в замерах не поднялась» и ещё несколько мелких причин.
- Ячеек с данными: 44 % со сдвигом −180 дн, 38 % без сдвига, 17 % исключено.
- Скважины: 122 с разметкой, 576 без разметки, 70 без телеметрии частоты (не используются).

## DataAuditReport  [6e6e8136]

Листы Excel и CSV нужны технологам: по ним видно, какие мероприятия не вошли в обучение и по какой причине.

## DataAuditReport.segments_table  [2de87646]
Таблица сегментов: по строке на отрезок календаря, где набор скважин с данными не менялся (след одной выгрузки). Столбцы: «начало», «конец», «дней», «скважин», «ячеек с данными», четыре столбца «доказательств» (по разметке и по исходной выгрузке, для сдвигов 0 и 180), «решение», «обоснование», «наложений».

«Доказательства» имеют вид `a/b`: подтверждено a из b проверенных; `—`, если проверять нечем (форматирует `_evidence`). Это лист «сегменты» в `data_audit.xlsx` (39 строк).

Пример — последний сегмент 2026 года:

| начало | конец | скважин | выгрузка, сдвиг 180 | решение |
|--------|-------|---------|---------------------|---------|
| 2026-09-04 | 2026-12-27 | 343 | 343/343 | сдвиг −180 дн |

Календарь, где ноябрь–декабрь 2026 ещё не наступили, — явный признак сдвинутого блока; сверка с исходной выгрузкой совпала у всех 343 скважин.

## DataAuditReport.non_numeric_by_month  [2bae061a]
Сколько заполненных ячеек статистики содержат не число (текст, дата), по месяцам. Месяцы без таких ячеек отбрасываются. Такие ячейки считаются пропусками. На текущих данных результат пустой, и в отчёте печатается «нет: все заполненные ячейки — числа»; лист «не числа» в Excel тогда пустой.

Возвращает `pd.Series` с `PeriodIndex` по месяцам.

## DataAuditReport.to_text  [38096abf]
Собирает консольный отчёт из пяти разделов:

1. Ячейки не с числом.
2. Сегменты и решения; в конце — доли ячеек по решениям («сдвиг −180 дн 74 050 ячеек (44%)»).
3. Воронка мероприятий итогового файла: сколько строк по каждой причине и таблица «год × принято / не принято».
4. Статусы скважин.
5. «Итог для обучения»: скважин с разметкой — 122, мероприятий — 135; скважин без разметки — 576 (по ним `predict` ищет мероприятия, но учиться на них нельзя).

Отдельно печатается, сколько из принятых мероприятий — «эффект продолжался» (censored; 40 из 135): у них неизвестен конец эффекта.

Принято по годам: 2021 — 14, 2022 — 29, 2023 — 25, 2024 — 17, 2025 — 0, 2026 — 50. За 2025 год принятых мероприятий нет (214 строк не принято).

## DataAuditReport.rejected_table  [c36df3a1]
Мероприятия, отброшенные по трём главным причинам из словаря `REJECTED` (скважины нет в статистике; нет замеров около даты начала; частота в замерах не поднялась). Добавляется столбец «пояснение» понятным языком; столбец «решение» переименован в «причина». Сортировка: причина, год, скважина. Возвращает `DataFrame` (на текущих данных 575 строк = 333 + 153 + 89).

Остальные причины (дубликат, не выполнено, частота не увеличена) технологам уточнять не нужно, поэтому в этот список они не входят.

## DataAuditReport.plot  [f7d2317b]
Рисует два графика один под другим с общими осями: число скважин с замерами по дням календаря «до исправления (как в файле)» и «после исправления». ## TrainingDataReport  [bfdd92a8]
Выгрузка «то, что видит модель». После исправления сдвигов и исключения сегментов берутся только скважины с принятой разметкой (122) и записываются в раскладке исходного файла статистики: лист на параметр, строка — скважина, столбец — дата. Так технолог может открыть файл и сравнить с исходным Excel.

Даты столбцов — непрерывный календарь от первого до последнего дня данных этих скважин (`pd.date_range`): с 30.06.2020, всего 2 257 дней плюс два служебных столбца «№ скв.» и «№ куста».

Листы файла `training_data.xlsx`:

| Лист | Содержимое |
|------|------------|
| `мероприятия` | 135 принятых строк разметки (заголовки как у технологов) |
| `Qж (из OIS)`, `Обв (из OIS)`, `Qн (из OIS)`, `Рлин (из OIS)`, `Fэцн ТМ(сут)`, `Рзаб` | замеры: 122 скважины × даты |
| `разметка по дням` | 1 — день эффекта, 0 — эффекта нет, пусто — день не участвует в обучении |

## TrainingDataReport.__init__  [fcdbde4d]
Принимает список скважин `wells` (из репозитория), `audit` и `context_days` (по умолчанию `CONTEXT_DAYS` = 45). Оставляет скважины с непустой разметкой, вычисляет общую ось дат — от самого раннего первого дня до самого позднего последнего.


## TrainingDataReport.labels_table  [e800bf21]
Принятые мероприятия (решение == `ACCEPTED`) из `audit.labels`; столбцы переименованы по `LABEL_HEADERS` в заголовки итогового файла технологов («Куст», «Скважина», «дата начала мониторинга», «Текущее значение», «Новое значение»…) и добавлен «эффект продолжался». Сортировка по скважине и дате начала. Столбец «строка Excel» позволяет найти исходную строку в файле технологов.

Пример: скважина 10335, куст 988, начало 14.08.2023, окончание 20.09.2023, частота 49,5 → 49,96 Гц, причина «прекращение эффекта по воде», строка Excel 307.

## TrainingDataReport.wide  [4c8d8e36]
Превращает ряды скважин (по одному `pd.Series` с датами в индексе на скважину, в порядке `self.wells`) в таблицу «скважина × дата». Каждый ряд приводится к общей оси дат (`reindex`, недостающие дни — пусто), заголовки столбцов дат — в формате `дд.мм.гггг`, перед ними столбцы «№ скв.» и «№ куста» (имена берутся из `MergedStatisticsReader`).

```python
table = report.wide([well.frame["frequency"] for well in report.wells])
# лист «Fэцн ТМ(сут)»: 122 строки, 2 259 столбцов
```

## TrainingDataReport.target_table  [c7171a06]
Таблица целевой переменной: для каждой скважины `well.target()` (1 — день внутри размеченного мероприятия) оставляется только там, где `training_mask(context_days)` истинна, остальное — пусто. Это в точности те дни, которые попадают в функцию потерь: ±45 дней вокруг размеченного мероприятия, без дней после censored-мероприятий.

На текущих данных в листе `разметка по дням` 9 034 нуля и 5 213 единиц; остальные ячейки пусты. Лист позволяет проверить, не обучается ли модель на днях, которые технолог не размечал.

## TrainingDataReport.save  [fd4bbb11]

На листах с таблицами закреплены заголовок и два первых столбца (`freeze_panes=(1, 2)`), чтобы номер скважины был виден при прокрутке. Возвращает путь.

## run  [0ddd635b]
Выполняет аудит: строит репозиторий (`MergedWellRepository(...).build()` — в отличие от `load()` возвращает ещё и `DataAudit`), печатает `to_text()`, сохраняет Excel, график и CSV, а затем `training_data.xlsx`. Печатает пути к файлам. Возвращает код выхода 0.

При `--no-reference` сверка с исходной выгрузкой не делается, решения принимаются только по разметке: быстрее, но у сегментов без мероприятий проверять нечем, и они остаются на месте.

```text
Таблицы: …\data_audit\data_audit.xlsx
График:  …\data_audit\data_audit.png
Отброшенные мероприятия: …\data_audit\rejected_labels.csv
Данные для обучения: …\data_audit\training_data.xlsx
```
