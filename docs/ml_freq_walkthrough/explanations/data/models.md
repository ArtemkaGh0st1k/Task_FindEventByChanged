## @module  [39009ed6]
Две структуры данных, на которых держится весь пакет: `Interval` (одно мероприятие) и `WellSeries` (скважина с суточными рядами и списком мероприятий). Читатели Excel (`readers.py`, `dataset.py`) их создают, `features.FeatureBuilder` превращает `WellSeries` в признаки, `evaluation` сравнивает предсказанные и размеченные `Interval`.

`SERIES_COLUMNS` — порядок шести измеряемых рядов: `frequency` (Гц), `debit_liquid` (м³/сут), `debit_oil`, `watercut` (обводнённость), `pressure_zab` (забойное давление), `pressure_line` (линейное давление). Ряды берутся из листов Excel «Fэцн», «Qж», «Qн», «Обв», «Рзаб», «Рлин».

### Пример
```python
from gtm_detector.ml_freq.data import SERIES_COLUMNS
SERIES_COLUMNS[0]   # 'frequency'
```

## Interval  [85167c35]
Одно мероприятие: период эффекта от `start` до `end` включительно (даты, не время). Неизменяемый объект.

- `end=None` — эффект длится до конца данных;
- `date_done` — «Дата выполнения» из листа «Результат__*» (только в разметке 2026 г.);
- `censored=True` — технолог написал «ПРОДОЛЖАЕТСЯ ЭФФЕКТ»: мониторинг остановили, эффект не закончился, поэтому `end` — не конец эффекта, а последний день наблюдения. После такого `end` нельзя считать «эффекта нет» (см. `training_mask`).

### Пример
Скважина 10335, куст 988, строка 307 итогового файла, и скважина 8814, куст 365:
```python
Interval(date(2023, 8, 14), date(2023, 9, 20))                # причина: «прекращение эффекта по воде»
Interval(date(2021, 7, 11), date(2021, 8, 12), censored=True)  # «ПРОДОЛЖАЕТСЯ ЭФФЕКТ»
```
Во втором случае технолог просто перестал наблюдать 12.08.2021; эффект мог идти и дальше.

## Interval.covers  [04227c31]
Попадает ли день `day` в период эффекта. Принимает `day` и `last_day` (последний день данных скважины), возвращает `bool`. Если `end=None`, правой границей служит `last_day`.

### Пример
```python
iv = Interval(date(2023, 8, 14), None)
iv.covers(date(2024, 1, 1), last_day=date(2024, 5, 1))   # True: эффект «до конца данных»
iv.covers(date(2023, 8, 13), last_day=date(2024, 5, 1))  # False: раньше начала
```

## WellSeries  [ec4f159a]
Скважина: `number` (номер, например `'10335'`), `cluster` (куст, `'988'`), `frame` — таблица `pandas`, индекс — подряд идущие календарные даты, столбцы — `SERIES_COLUMNS` и `state` (1 — скважина работает), `labels` — список `Interval`. Обычный (не frozen) dataclass: читатели дописывают разметку в `labels` после создания.

Календарь непрерывный, пропущенные дни остаются `NaN` — признаки сами учитывают пропуски, а не выбрасывают строки.

### Пример
Скважина `10335/988` из объединённой статистики: `frame` с 03.06.2023 по 01.05.2024 (334 дня), 7 столбцов, `labels` из одного `Interval` (14.08.2023 – 20.09.2023). Всего `MergedWellRepository.build()` даёт 698 скважин, из них 122 с разметкой.

## WellSeries.well_id  [2036cc2a]
Строка `"номер/куст"` — удобный идентификатор для логов и отчётов, где одного номера мало (на разных кустах номера могут повторяться).

### Пример
`WellSeries(number='10335', cluster='988', ...).well_id == '10335/988'`.

## WellSeries.dates  [b33d0545]
Список обычных `datetime.date` по индексу `frame` (без времени), в том же порядке, что и строки таблицы. Нужен там, где даты сравнивают с `Interval.start/end`, которые тоже `date`.

### Пример
Для `10335/988`: `dates[0] == date(2023, 6, 3)`, `dates[-1] == date(2024, 5, 1)`.

## WellSeries.__len__  [49786f26]
Число дней в `frame`. Позволяет писать `len(well)`.

### Пример
`len(well) == 334` для `10335/988` (с 03.06.2023 по 01.05.2024 включительно).

## WellSeries.target  [cba3828a]
Целевой вектор для обучения: массив `float32` длиной `len(self)`, 1.0 в днях внутри любого размеченного периода, 0.0 вне. Если у мероприятия `end=None`, период идёт до последнего дня `frame`.

Важно: 0 здесь означает «в разметке эффекта нет», а не «эффекта точно нет» — разметка неполная. Поэтому `target` используют только вместе с `training_mask`.

### Пример
Для `10335/988` период 14.08–20.09.2023 даёт `target().sum() == 38.0`; для `8814/365` (11.07–12.08.2021) — 33.0.

## WellSeries.training_mask  [adbc4998]
Булев массив длиной `len(self)`: дни, на которых модель вправе учиться (попадают в функцию потерь). Параметр `context_days` — окно в днях (в проекте `CONTEXT_DAYS = 45`); `None` — все дни.

Для каждого мероприятия берутся дни от `start − context_days` до `end + context_days`. Причина: технологи размечают не все подъёмы частоты, поэтому далёкие от разметки дни нельзя считать отрицательными примерами. Исключение — `censored`: после `end` эффект неизвестен, поэтому окно заканчивается ровно на `end`, а дни после не берутся.

### Пример
```python
well_10335.training_mask(45).sum()   # 128: с 30.06.2023 по 04.11.2023
well_8814.training_mask(45).sum()    # 78: censored, правая граница = 12.08.2021 без запаса
well_10335.training_mask(None).sum() # 334, то есть вся скважина
```
У 10335: 45 дней до + 38 дней эффекта + 45 дней после = 128. У 8814: 45 до + 33 дня эффекта = 78, потому что после `censored`-окончания дни не берутся.
