## @module  [7b906721]
Читатели исходных файлов **тестового** набора 2026 г. (`resources/test_datas/`): замеры `input_dataset.xlsx` (лист на параметр, строка — скважина, столбец — дата `ДД.ММ.ГГГГ`) и разметка `output_dataset.xlsm` (лист «Результат__*»). Основной набор 2021–2026 читает `statistics.py`, но он берёт отсюда `normalize_id`, `parse_date`, а `dataset.py` — `MeasurementsReader.read_parameter` (для исходной выгрузки, по которой проверяются сдвиги).

`WellRepository` собирает замеры и разметку в список `WellSeries` и кэширует результат в `%TEMP%/gtm_ml_freq_cache`.

### Пример
```python
from gtm_detector.ml_freq.data import WellRepository
from gtm_detector.ml_freq.config import DataConfig
c = DataConfig()
wells = WellRepository(c.measurements, c.results).load()   # 516 скважин; первый запуск ~30 с
```

## normalize_id  [5fc31ffd]
Приводит номер скважины или куста к одному виду. Принимает что угодно из ячейки Excel (строка, число, `NaN`, `None`), возвращает строку: обрезает пробелы, переводит в верхний регистр и заменяет **латинские буквы, похожие на русские**, на кириллицу (A→А, E→Е, K→К, M→М, H→Н, O→О, P→Р, C→С, T→Т, X→Х). Целые числа в `float` (`7782.0`) превращает в `'7782'`; пустое значение даёт `""`.

Нужно потому, что номера набирают вперемешку латиницей и кириллицей, а скважина — ключ для объединения замеров и разметки.

### Пример
```python
normalize_id('561E ')    # '561Е'  (латинская E стала русской Е)
normalize_id(7782.0)     # '7782'
normalize_id(None)       # ''
normalize_id('2015Б')    # '2015Б'
```

## parse_date  [43ab7784]
Достаёт дату из ячейки разметки, терпя опечатки технологов. Принимает `Timestamp`/`date`/текст/`NaN`, возвращает `date` или `None`. В тексте ищется шаблон `д.м.гг(гг)`, поэтому `'21.04.2026г'` работает. Год `206` (потерянная цифра) исправляется на 2026, `26` — тоже на 2026. Даты раньше 2000 года и несуществующие (31.02) дают `None`, чтобы мусор из Excel не попадал в разметку.

### Пример
```python
parse_date('21.04.2026г')               # date(2026, 4, 21)
parse_date('08.02.206')                 # date(2026, 2, 8)
parse_date('abc')                       # None
parse_date(pd.Timestamp('2023-08-14'))  # date(2023, 8, 14)
```

## MeasurementsReader  [da5e7fc3]
Читает файл замеров (`input_dataset.xlsx`) в список `WellSeries` **без разметки**. Константа `SHEETS` связывает параметр и лист Excel: `frequency` — «Fэцн ТМ», `debit_liquid` — «Qж», `debit_oil` — «Qн», `watercut` — «Обв», `pressure_zab` — «Рзаб», `pressure_line` — «Pлин». `STATE_SHEET = "Прим"` — лист с состоянием скважины, `WORKING_STATES` — значения «работает» (`раб.`, `нак`).

### Пример
В тестовом файле 516 скважин с 01.01.2026 по 31.08.2026; у первой (`124/2079`) насос работал примерно в 98 % дней.

## MeasurementsReader.__init__  [216533a2]
Запоминает путь к файлу (`Path`). Файл не открывается до вызова `read`.

### Пример
`MeasurementsReader(DataConfig().measurements)`.

## MeasurementsReader.read  [7cfc2f5d]
Основной метод: читает все шесть листов параметров и лист «Прим», строит единый **непрерывный календарь** от минимальной до максимальной даты листа частоты и для каждой скважины из листа частоты создаёт `WellSeries`. Если параметра у скважины нет — столбец из `NaN`. Столбец `state`: из листа «Прим» (`раб.`/`нак` → 1), а если скважины там нет — «частота > 0». Возвращает `list[WellSeries]`, все столбцы приведены к `float`.

Скважины берутся по листу частоты: без телеметрии частоты задача бессмысленна.

### Пример
Первая скважина тестового файла — `124/2079`, календарь 01.01.2026 – 31.08.2026, `frame['state'].mean()` ≈ 0,98.

## MeasurementsReader.read_parameter  [01814849]
Читает **один** лист параметра и возвращает таблицу «скважина × дата»: индекс `MultiIndex(номер, куст)` после `normalize_id`, столбцы — `Timestamp`. Шапка листа — вторая строка (`header=1`), строка-подзаголовок под ней (`iloc[1:]`) отбрасывается. Столбцами считаются и настоящие даты, и строки `ДД.ММ.ГГГГ`; значения приводятся `to_numeric(errors='coerce')`, повторы скважин удаляются. Метод публичный, потому что `MergedWellRepository._reference` читает им лист «Qж» исходной выгрузки.

### Пример
```python
MeasurementsReader(c.reference).read_parameter("Qж")   # таблица «скважины × даты 2026 г.»
```

## MeasurementsReader._read_states  [518497c5]
Читает лист «Прим» (без шапки) и возвращает таблицу состояний «скважина × дата» из **строк**, где в пятом столбце написано «Состояние». Отдельного столбца куста здесь нет: куст вынут регулярным выражением `куст\s+([^,]+)` из строки «Прим» под строкой состояния («…, куст 2079, …»). Значения очищаются от пробелов (`'раб.'`, `'нак'` и т. п.); повторы скважин отбрасываются.

### Пример
Для `124/2079` строка состояния содержит «раб.» почти во всех днях, куст `2079` берётся из соседней строки примечания.

## LabelsReader  [09c7fac8]
Читает разметку из листа «Результат__*» файла `output_dataset.xlsm`. `COLUMNS` — номера столбцов (с нуля) → имена: 3 — куст, 4 — номер скважины, 26 — тип мероприятия, 35 — дата выполнения, 39 — успешность, 41/42 — даты начала/окончания мониторинга. Шапка занимает 4 строки (`skiprows=4`).

### Пример
В тестовой разметке 105 скважин и 117 мероприятий «Увеличение F» (успешных, с обеими датами).

## LabelsReader.__init__  [a20d906c]
Принимает путь к файлу и, при желании, имя листа; без имени берётся первый лист, название которого начинается с «Результат».

### Пример
`LabelsReader(DataConfig().results)` — лист находится сам.

## LabelsReader.read  [4c7f5321]
Возвращает словарь `{(номер, куст): [Interval, ...]}`. В разметку попадают только строки с типом «Увеличение F», успешные («да»), у которых обе даты распознаны `parse_date` и окончание не раньше начала. В `Interval` записывается и `date_done`. Число принятых мероприятий пишется в лог.

### Пример
```python
LabelsReader(c.results).read()   # 105 ключей (скважин), 117 мероприятий
```

## WellRepository  [011d36d6]
Фасад над читателями для **тестового** набора: замеры + разметка → готовые скважины. Кэш — файл `wells_<отпечаток>.pkl` в `%TEMP%/gtm_ml_freq_cache`.

### Пример
`WellRepository(c.measurements, c.results).load()` вернёт 516 скважин; разметка привязана к тем, где ключ `(номер, куст)` совпал.

## WellRepository.__init__  [a2dcf3f3]
Принимает путь к замерам, путь к разметке (может быть `None` — тогда скважины без разметки, например для предсказания) и необязательную папку кэша. По умолчанию кэш лежит во временной папке системы.

### Пример
`WellRepository(c.measurements, None)` — только замеры.

## WellRepository.load  [c79ff67c]
Возвращает `list[WellSeries]`. Сначала ищет файл кэша по отпечатку; если есть — читает `pickle`. Иначе читает Excel (около 30 секунд), привязывает разметку и записывает кэш. Поэтому первое чтение долгое, а дальнейшие — за секунды.

### Пример
Первый вызов ~30 с, повторный — доли секунды. Ключ кэша зависит только от файлов данных, а не от кода: после правки `readers.py` кэш может быть устаревшим — папку кэша надо удалить.

## WellRepository._attach  [3c7dd12a]
Статический метод: дописывает интервалы из словаря разметки в `labels` скважин (на месте, ничего не возвращает). Ключ — `(номер, куст)`. Если пары нет, но скважина с таким номером **одна**, берётся она («куст записан иначе, но номер уникален»). Остальные мероприятия считаются потерянными, их число пишется предупреждением в лог.

### Пример
Разметка `('124', '2079')`, а в замерах куст записан иначе: пара не найдена, но номер 124 один — разметка привяжется. Если скважин с таким номером две, мероприятие уйдёт в «не найдено».

## WellRepository._fingerprint  [68615cb7]
Короткий хэш (12 символов SHA-1) от абсолютных путей, размеров и времён изменения файлов замеров и разметки. Любая правка Excel меняет хэш, и кэш пересчитывается.

### Пример
Имя вида `wells_<12 hex-символов>.pkl` в `%TEMP%/gtm_ml_freq_cache`.
