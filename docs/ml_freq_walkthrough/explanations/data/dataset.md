## @module  [a33d9b86]
Сборка итогового набора скважин из файлов статистики 2020–2026 и отчёт о том, что и почему не попало в обучение. Это последний шаг пакета `data`: его результат (`list[WellSeries]` с проверенной разметкой) идёт в `features` и `evaluation`.

Порядок работы `MergedWellRepository._build`:

1. читаются числовые ячейки статистики — из папки полугодовых `.xls` (`HalfYearStatisticsReader`) или из склеенного файла (`MergedStatisticsReader`) — и 786 строк разметки (`MonitoringLabelsReader`);
2. отсев разметки по причинам, видным без замеров (`_prefilter`);
3. **только для склеенного файла** (`statistics.is_file()`): поиск и исправление сдвинутых на 180 дней блоков (`BlockShiftRepair`, `_repair`); в исходных полугодовых файлах сдвига нет, шаг пропускается;
4. скважины без телеметрии частоты не используются: подъём F на них не увидеть;
5. каждое оставшееся мероприятие проверяется по замерам (`_verify`); берутся те, у которых частота около даты начала действительно поднялась (`FrequencyCheck`).

### Пример
```python
from gtm_detector.ml_freq.config import DataConfig
from gtm_detector.ml_freq.data import MergedWellRepository
c = DataConfig()
wells, audit = MergedWellRepository(c.statistics, c.labels, c.reference).build()
len(wells)                              # 611 скважин в обучении/проверке
sum(1 for w in wells if w.labels)       # 369 скважин с разметкой
sum(len(w.labels) for w in wells)       # 424 мероприятия
audit.labels["решение"].value_counts()  # причины отказа по каждой из 786 строк
```
Это та же таблица, что в `results/ml_freq/data_audit_halfyear/data_audit.xlsx`; CLI-команда `audit` пишет её в файлы.

## DataAudit  [17b3f367]
Отчёт о сборке (обычный dataclass; пишется в кэш вместе со скважинами). Поля:

| Поле | Что содержит |
|---|---|
| `segments` | список `Segment` с решением по каждому сегменту (39 сегментов склеенного файла: 25 без сдвига, 7 со сдвигом −180, 7 исключено; для полугодовых файлов список пуст) |
| `labels` | таблица всех 786 строк итогового файла + столбец «решение» |
| `wells` | таблица по скважинам: дни с замерами, доля дней с частотой > 10 Гц, число принятых мероприятий, статус |
| `non_numeric` | число заполненных, но нечисловых ячеек по датам |
| `wells_per_day_before` / `_after` | скважин с данными по дням до и после исправления |
| `reference` | путь к эталонной выгрузке (склеенный файл) или `None` |

### Пример
Распределение столбца «решение» на полугодовых файлах: принято 424, частота в замерах не поднялась 313, дубликат 40, нет телеметрии частоты у скважины 5, «частота не увеличена» 3, не выполнено 1 (сумма 786). Статусы скважин: 242 «используется, без разметки», 369 «используется, с разметкой», 5 «не используется: нет телеметрии частоты» (всего 616). Для прежнего склеенного файла картина была иной: принято 135, скважины нет в статистике 333, нет замеров около даты 153, частота не поднялась 89.

## MergedWellRepository  [c8766fc9]
Скважины с проверенной разметкой; результат кэшируется (`merged_<хэш>.pkl` в `%TEMP%/gtm_ml_freq_cache`). `statistics` — папка с полугодовыми файлами или один склеенный файл. Константы: `VERSION = 2` (менять при изменении логики — сбрасывает кэш), `MIN_TELEMETRY_SHARE = 0,1` (доля дней с замерами, где частота > 10 Гц; ниже — скважина не используется) и `DATA_WINDOW = 14` дней вокруг даты начала, где должны быть замеры.

### Пример
Первое построение читает Excel около 30 секунд; потом `build()` берёт готовый результат из кэша за секунды.

## MergedWellRepository.__init__  [38b40ddb]
Принимает пути: `statistics`, `labels` (может быть `None` — тогда разметки нет), `reference` (исходная выгрузка; если файла нет, считается `None` и сверки по ней не будет), `cache_dir` (по умолчанию `%TEMP%/gtm_ml_freq_cache`), `repair` (по умолчанию `BlockShiftRepair()`). Запоминает также `self.check = repair.check` — тот же `FrequencyCheck`, что использует починка, чтобы проверка подъёма везде была одной.

### Пример
```python
MergedWellRepository(c.statistics, c.labels, c.reference)   # reference = None для полугодовых файлов
MergedWellRepository(c.statistics, None)   # только скважины, без разметки
```

## MergedWellRepository.load  [85fea856]
Короткий путь: только список скважин, `build()[0]`. Его вызывает обучение, а отчёт `DataAudit` нужен только команде `audit`.

### Пример
`MergedWellRepository(c.statistics, c.labels, c.reference).load()` → 611 `WellSeries`.

## MergedWellRepository.build  [f070e761]
Возвращает пару `(скважины, DataAudit)`. Если файл кэша с отпечатком `_fingerprint()` есть — читает `pickle`; иначе вызывает `_build` и записывает кэш. Отпечаток включает версию, `repr` починки и параметры файлов, поэтому смена порогов или данных сама сбрасывает кэш; правки кода в `readers.py`/`statistics.py` кэш не видит (кроме смены `VERSION`) — тогда папку нужно удалить.

### Пример
`wells, audit = repo.build()`; повторный вызов — «Данные из кэша: …/merged_<хэш>.pkl» в логе.

## MergedWellRepository._build  [84712356]
Вся сборка без кэша.

- Выбирает читателя: `statistics.is_file()` — склеенный `MergedStatisticsReader`, иначе `HalfYearStatisticsReader` (папка).
- Читает таблицы параметров, объединяет индексы скважин всех листов и приводит таблицы к общему индексу и календарю частоты. `presence` — матрица «есть ли хоть какое-то значение».
- Читает разметку, `_prefilter` даёт причины и строку скважины; для записей без отказа строятся `LabelPoint`.
- Для склеенного файла: строит `LabelPoint` и вызывает `_repair` (сегментирование, оценка, применение; вердикты сегментов — в лог). Для полугодовых файлов сегментов нет, таблицы идут дальше как есть.
- По исправленным данным считает `has_data`, долю телеметрии и «дни исключённых сегментов», проверяет оставшиеся мероприятия через `_verify`, собирает скважины `_wells` и `DataAudit`.

### Пример
Лог на полугодовых файлах: «Статистика: 14 файлов, 616 скважин, 2498 дат» и итог «Скважин: 611, с разметкой: 369, мероприятий: 424». Для склеенного файла в лог ещё шли строки вида «Сегмент 2026-09-04 — 2026-12-27: сдвиг −180 дн (совпадает с исходной выгрузкой: 343 из 343 скважин)».

## MergedWellRepository._repair  [49116b66]
Вынесенный из `_build` блок исправления сдвигов, который запускается **только для склеенного файла**. Принимает таблицы параметров, матрицу присутствия `presence`, список `LabelPoint` (проверяемые мероприятия), общий индекс и календарь. Берёт эталонную выгрузку (`_reference`), делит календарь на сегменты, оценивает их (`assess`) и применяет решения (`apply`: сдвинуть на −180 дней, исключить или оставить), пишет вердикты в лог. Возвращает пару `(segments, repaired)`.

Для полугодовых файлов `_build` эту функцию не вызывает: `segments == []`, таблицы идут дальше без изменений.

### Пример
Склеенный файл: `segments, repaired = repo._repair(...)` -> 39 сегментов (25 без сдвига, 7 со сдвигом −180, 7 исключено). Папка `resources/statistics`: функция не вызывается, а `DataAudit.segments` пуст и лист «сегменты» в `data_audit.xlsx` тоже.

## MergedWellRepository._prefilter  [132c61a4]
Статический метод. Для каждой записи разметки находит строку скважины в таблицах (по `(номер, куст)`; если такой пары нет, но номер уникален — по номеру) и причину отказа, видную без замеров. Возвращает два списка: `decisions` (`None` — пока годится, иначе текст) и `rows` (индекс строки или `None`). Порядок проверок: `MonitoringLabelsReader.rejection`; дубликат (одна скважина и та же дата начала — оставляется первая строка); «скважины нет в статистике».

### Пример
Из 786 записей здесь отсеивается 40 «дубликат», 3 «частота не увеличена» и 1 «не выполнено»; «скважины нет в статистике» теперь нет ни у одной строки (в полугодовых файлах 616 скважин). В прежнем склеенном файле таких было 333.

## MergedWellRepository._verify  [c482e0cf]
Проверка одной записи по замерам после починки. Возвращает «решение» — `ACCEPTED` («принято») или причину отказа:

1. дата начала вне календаря → «дата начала вне календаря статистики»;
2. нет ни одного замера в окне ±14 дней от начала: если там были данные исключённого сегмента — «замеры около даты начала — в исключённом сегменте», иначе «нет замеров около даты начала»;
3. доля телеметрии скважины < 0,1 → «нет телеметрии частоты у скважины»;
4. `FrequencyCheck.confirms` вернул `None` → «нет замеров частоты около даты начала», `False` → «частота в замерах не поднялась около даты начала», `True` → принято.

### Пример
10335/988, начало 14.08.2023: замеры есть, доля телеметрии высокая, частота 49,5 → 51,5 Гц → «принято». Скважина 10784/179, начало 23.08.2021 (148 → 150,77 Гц по разметке; строка Excel 79): частота в ±3 дня не выросла ни до «Нового значения», ни на половину прироста — в `rejected_labels.csv` «частота в замерах не поднялась около даты начала».

## MergedWellRepository._wells  [4b150ffd]
Собирает `WellSeries` и таблицу по скважинам. Сначала группирует принятые мероприятия по строкам скважин в `Interval(start, end, censored=…)`. Для каждой строки таблиц задаёт статус: «нет данных после исправления» (ни одного дня с данными), «не используется: нет телеметрии частоты» (доля < 0,1) или «используется, с разметкой»/«используется, без разметки». Для используемых строится `frame` от первого до последнего дня с данными, столбцы `SERIES_COLUMNS`, `state = (frequency > 0)`; интервалы сортируются по началу. Возвращает `(wells, строки таблицы)`.

### Пример
Скважина 10335/988: `frame` 01.01.2020 – 18.03.2026 (2269 дней), 1 мероприятие 14.08–20.09.2023, статус «используется, с разметкой». Статус по всем 616 строкам: 242 «без разметки» / 369 «с разметкой» / 5 «не используется».

## MergedWellRepository._reference  [66d460d6]
Исходная выгрузка (лист «Qж» файла `input_dataset.xlsx`) в координатах склеенной таблицы: индекс скважин и календарь те же, нет данных — `NaN`. Только для сверки сдвигов; в обучение не идёт. Без `reference` возвращает `None`.

### Пример
Нужна только для склеенного файла (для папки полугодий `reference = None`, и функция возвращает `None`). Раньше: матрица 768 × 2557, заполненная только на 2026 г.

## MergedWellRepository._telemetry_share  [1665bbe5]
Для каждой скважины: доля дней с данными, в которые частота выше `FrequencyCheck.MIN_WORKING` (10 Гц). Принимает массив частоты (`NaN` → 0) и матрицу `has_data`; для скважины без данных — 0. Возвращает массив долей от 0 до 1.

### Пример
Скважина, у которой данные есть 200 дней и частота > 10 Гц в 20 из них, получает 0,1 — на пороге `MIN_TELEMETRY_SHARE`. Таких «слепых» скважин с долей < 0,1 в полугодовых данных 5 (в склеенном файле было 70).

## MergedWellRepository._dropped_days  [15cc38d0]
Матрица «скважина × день»: `True` там, где данные были в исходном файле, но сегмент исключён. Нужна `_verify`, чтобы объяснить отказ («замеры около даты начала — в исключённом сегменте»), а не писать просто «нет замеров».

### Пример
Только для склеенного файла: если сегмент 01.06.2023 – 30.10.2023 исключён (сдвиг не подтвердился ни разметкой, ни эталоном), мероприятие с датой начала в нём получает причину «замеры около даты начала — в исключённом сегменте» (в склеенном файле таких отказов было 14). На полугодовых файлах исключённых сегментов нет, матрица пуста.

## MergedWellRepository._labels_table  [eef06e60]
Таблица для `DataAudit.labels`: столбцы «строка Excel», «скважина», «куст», «год», «тип ГТМ», «начало», «окончание», «частота до, Гц», «частота после, Гц», «причина окончания», «эффект продолжался», «решение». Для каждой из 786 записей одна строка.

### Пример
Строка Excel 307: скважина 10335, куст 988, 2023, 14.08.2023 – 20.09.2023, 49.5 → 49.96 Гц, «прекращение эффекта по воде», эффект продолжался — False, решение «принято».

## MergedWellRepository._fingerprint  [44db98fc]
12-символьный хэш SHA-1 от версии (`v2`), `repr(self.repair)` и путей, размеров и времён изменения всех исходных файлов: для папки — каждого из 14 `.xls` (список даёт `HalfYearStatisticsReader.files()`), для склеенного файла — одного файла; плюс разметка и эталонная выгрузка, если она есть. Меняется при замене любого Excel или правке порогов починки — кэш тогда пересчитывается.

### Пример
`merged_<12 hex-символов>.pkl`; смена `min_flip=5` на 3 даёт новое имя файла.
