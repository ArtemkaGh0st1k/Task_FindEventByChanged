## @module  [b8b13ca4]
Сборка итогового набора скважин из объединённых файлов 2021–2026 и отчёт о том, что и почему не попало в обучение. Это последний шаг пакета `data`: его результат (`list[WellSeries]` с проверенной разметкой) идёт в `features` и `evaluation`.

Порядок работы `MergedWellRepository._build`:

1. читаются числовые ячейки статистики (`MergedStatisticsReader`) и 786 строк разметки (`MonitoringLabelsReader`);
2. отсев разметки по причинам, видным без замеров (`_prefilter`);
3. поиск и исправление сдвинутых на 180 дней блоков (`BlockShiftRepair`, при наличии исходной выгрузки 2026 г. как эталон);
4. скважины без телеметрии частоты не используются: подъём F на них не увидеть;
5. каждое оставшееся мероприятие проверяется по замерам (`_verify`); берутся те, у которых частота около даты начала действительно поднялась (`FrequencyCheck`).

### Пример
```python
from gtm_detector.ml_freq.config import DataConfig
from gtm_detector.ml_freq.data import MergedWellRepository
c = DataConfig()
wells, audit = MergedWellRepository(c.statistics, c.labels, c.reference).build()
len(wells)                              # 698 скважин в обучении/проверке
sum(1 for w in wells if w.labels)       # 122 скважины с разметкой
sum(len(w.labels) for w in wells)       # 135 мероприятий
audit.labels["решение"].value_counts()  # причины отказа по каждой из 786 строк
```
Это та же таблица, что в `results/ml_freq/data_audit/data_audit.xlsx`; CLI-команда `audit` пишет её в файлы.

## DataAudit  [17b3f367]
Отчёт о сборке (обычный dataclass; пишется в кэш вместе со скважинами). Поля:

| Поле | Что содержит |
|---|---|
| `segments` | список `Segment` с решением по каждому сегменту (39 сегментов: 25 без сдвига, 7 со сдвигом −180, 7 исключено) |
| `labels` | таблица всех 786 строк итогового файла + столбец «решение» |
| `wells` | таблица по скважинам: дни с замерами, доля дней с частотой > 10 Гц, число принятых мероприятий, статус |
| `non_numeric` | число заполненных, но нечисловых ячеек по датам |
| `wells_per_day_before` / `_after` | скважин с данными по дням до и после исправления |
| `reference` | путь к исходной выгрузке 2026 г. или `None` |

### Пример
Распределение столбца «решение»: принято 135, скважины нет в статистике 333, нет замеров около даты начала 153, частота в замерах не поднялась 89, дубликат 30, нет замеров частоты около начала 26, замеры в исключённом сегменте 14, «частота не увеличена» 3, нет телеметрии 2, не выполнено 1 (сумма 786). Статусы скважин: 576 «используется, без разметки», 122 «используется, с разметкой», 70 «не используется: нет телеметрии частоты».

## MergedWellRepository  [2c4a0ab9]
Скважины с проверенной разметкой из объединённых файлов; результат кэшируется (`merged_<хэш>.pkl` в `%TEMP%/gtm_ml_freq_cache`). Константы: `VERSION = 1` (менять при изменении логики — сбрасывает кэш), `MIN_TELEMETRY_SHARE = 0,1` (доля дней с замерами, где частота > 10 Гц; ниже — скважина не используется) и `DATA_WINDOW = 14` дней вокруг даты начала, где должны быть замеры.

### Пример
Первое построение читает Excel около 30 секунд; потом `build()` берёт готовый результат из кэша за секунды.

## MergedWellRepository.__init__  [38b40ddb]
Принимает пути: `statistics`, `labels` (может быть `None` — тогда разметки нет), `reference` (исходная выгрузка; если файла нет, считается `None` и сверки по ней не будет), `cache_dir` (по умолчанию `%TEMP%/gtm_ml_freq_cache`), `repair` (по умолчанию `BlockShiftRepair()`). Запоминает также `self.check = repair.check` — тот же `FrequencyCheck`, что использует починка, чтобы проверка подъёма везде была одной.

### Пример
```python
MergedWellRepository(c.statistics, c.labels, c.reference)
MergedWellRepository(c.statistics, None)   # только скважины, без разметки
```

## MergedWellRepository.load  [85fea856]
Короткий путь: только список скважин, `build()[0]`. Его вызывает обучение, а отчёт `DataAudit` нужен только команде `audit`.

### Пример
`MergedWellRepository(c.statistics, c.labels, c.reference).load()` → 698 `WellSeries`.

## MergedWellRepository.build  [f070e761]
Возвращает пару `(скважины, DataAudit)`. Если файл кэша с отпечатком `_fingerprint()` есть — читает `pickle`; иначе вызывает `_build` и записывает кэш. Отпечаток включает версию, `repr` починки и параметры файлов, поэтому смена порогов или данных сама сбрасывает кэш; правки кода в `readers.py`/`statistics.py` кэш не видит — тогда папку нужно удалить.

### Пример
`wells, audit = repo.build()`; повторный вызов — «Данные из кэша: …/merged_<хэш>.pkl» в логе.

## MergedWellRepository._build  [328ae9b0]
Вся сборка без кэша.

- Читает таблицы параметров, объединяет индексы скважин всех листов и приводит таблицы к общему индексу и календарю частоты. `presence` — матрица «есть ли хоть какое-то значение».
- Читает разметку, `_prefilter` даёт причины и строку скважины; для записей без отказа строятся `LabelPoint`.
- Сегментирует, оценивает и применяет починку; пишет в лог вердикты сегментов.
- По исправленным данным считает `has_data`, долю телеметрии и «дни исключённых сегментов», проверяет оставшиеся мероприятия через `_verify`, собирает скважины `_wells` и `DataAudit`.

### Пример
Лог: «Сегмент 2026-09-04 — 2026-12-27: сдвиг −180 дн (совпадает с исходной выгрузкой: 343 из 343 скважин)» и итог «Скважин: 698, с разметкой: 122, мероприятий: 135».

## MergedWellRepository._prefilter  [132c61a4]
Статический метод. Для каждой записи разметки находит строку скважины в таблицах (по `(номер, куст)`; если такой пары нет, но номер уникален — по номеру) и причину отказа, видную без замеров. Возвращает два списка: `decisions` (`None` — пока годится, иначе текст) и `rows` (индекс строки или `None`). Порядок проверок: `MonitoringLabelsReader.rejection`; дубликат (одна скважина и та же дата начала — оставляется первая строка); «скважины нет в статистике».

### Пример
Из 786 записей здесь отсеивается 333 «скважины нет в статистике» (в статистике 768 скважин, а разметка относится и к другим), 30 «дубликат», 3 «частота не увеличена» и 1 «не выполнено».

## MergedWellRepository._verify  [c482e0cf]
Проверка одной записи по замерам после починки. Возвращает «решение» — `ACCEPTED` («принято») или причину отказа:

1. дата начала вне календаря → «дата начала вне календаря статистики»;
2. нет ни одного замера в окне ±14 дней от начала: если там были данные исключённого сегмента — «замеры около даты начала — в исключённом сегменте», иначе «нет замеров около даты начала»;
3. доля телеметрии скважины < 0,1 → «нет телеметрии частоты у скважины»;
4. `FrequencyCheck.confirms` вернул `None` → «нет замеров частоты около даты начала», `False` → «частота в замерах не поднялась около даты начала», `True` → принято.

### Пример
10335/988, начало 14.08.2023: замеры есть, доля телеметрии высокая, частота 49,5 → 51,5 Гц → «принято». Скважина 10738, начало 13.08.2021 — в `rejected_labels.csv` «нет замеров около даты начала».

## MergedWellRepository._wells  [4b150ffd]
Собирает `WellSeries` и таблицу по скважинам. Сначала группирует принятые мероприятия по строкам скважин в `Interval(start, end, censored=…)`. Для каждой строки таблиц задаёт статус: «нет данных после исправления» (ни одного дня с данными), «не используется: нет телеметрии частоты» (доля < 0,1) или «используется, с разметкой»/«используется, без разметки». Для используемых строится `frame` от первого до последнего дня с данными, столбцы `SERIES_COLUMNS`, `state = (frequency > 0)`; интервалы сортируются по началу. Возвращает `(wells, строки таблицы)`.

### Пример
Скважина 10335/988: `frame` 03.06.2023 – 01.05.2024, 1 мероприятие 14.08–20.09.2023, статус «используется, с разметкой». Статус по всем 768 строкам: 576 / 122 / 70.

## MergedWellRepository._reference  [66d460d6]
Исходная выгрузка (лист «Qж» файла `input_dataset.xlsx`) в координатах склеенной таблицы: индекс скважин и календарь те же, нет данных — `NaN`. Только для сверки сдвигов; в обучение не идёт. Без `reference` возвращает `None`.

### Пример
Матрица 768 × 2557; заполнена только на 2026 г. (01.01–31.08.2026).

## MergedWellRepository._telemetry_share  [1665bbe5]
Для каждой скважины: доля дней с данными, в которые частота выше `FrequencyCheck.MIN_WORKING` (10 Гц). Принимает массив частоты (`NaN` → 0) и матрицу `has_data`; для скважины без данных — 0. Возвращает массив долей от 0 до 1.

### Пример
Скважина, у которой данные есть 200 дней и частота > 10 Гц в 20 из них, получает 0,1 — на пороге `MIN_TELEMETRY_SHARE`. Таких «слепых» скважин с долей < 0,1 в данных 70.

## MergedWellRepository._dropped_days  [15cc38d0]
Матрица «скважина × день»: `True` там, где данные были в исходном файле, но сегмент исключён. Нужна `_verify`, чтобы объяснить отказ («замеры около даты начала — в исключённом сегменте»), а не писать просто «нет замеров».

### Пример
Сегмент 01.06.2023 – 30.10.2023 исключён (сдвиг не подтвердился ни разметкой, ни эталоном). Мероприятие, дата начала которого попадает в такой период, получает причину «замеры около даты начала — в исключённом сегменте»; всего таких отказов 14.

## MergedWellRepository._labels_table  [eef06e60]
Таблица для `DataAudit.labels`: столбцы «строка Excel», «скважина», «куст», «год», «тип ГТМ», «начало», «окончание», «частота до, Гц», «частота после, Гц», «причина окончания», «эффект продолжался», «решение». Для каждой из 786 записей одна строка.

### Пример
Строка Excel 307: скважина 10335, куст 988, 2023, 14.08.2023 – 20.09.2023, 49.5 → 49.96 Гц, «прекращение эффекта по воде», эффект продолжался — False, решение «принято».

## MergedWellRepository._fingerprint  [02ee14fd]
12-символьный хэш SHA-1 от версии (`v1`), `repr(self.repair)` и путей, размеров и времён изменения трёх файлов (статистика, разметка, исходная выгрузка). Меняется при правке Excel или порогов починки — кэш тогда пересчитывается.

### Пример
`merged_<12 hex-символов>.pkl`; смена `min_flip=5` на 3 даёт новое имя файла.
