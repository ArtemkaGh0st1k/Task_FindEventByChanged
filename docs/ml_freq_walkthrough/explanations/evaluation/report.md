## @module  [65afeb3a]
Последний шаг команды `compare`: результаты моделей (`list[ModelResult]`) превращаются в файлы, которые можно открыть без Python, — Excel-таблицу `comparison.xlsx` и картинку `comparison.png`. Расчётов здесь нет, только оформление.

В папке `results/ml_freq/comparison_merged/` лежат файлы, переименованные вручную («сравнение_качества_моделей_(21-26 год).xlsx» и `.png`); команда создаёт их под именами `comparison.xlsx` и `comparison.png`.

## ComparisonReport  [035b4c07]
Отчёт по списку `ModelResult`. Создаётся в `cli.run_compare`:

```python
report = ComparisonReport(results)
report.save(out_dir)          # comparison.xlsx + comparison.png
print(report.to_text())       # короткая таблица в консоль
```

Атрибут `KEY_METRICS` — шесть главных метрик, они попадают на график и в консольную таблицу: recall, «начало: точно», «начало: ±3 дн», «конец: точно», «конец: ±7 дн», «ROC-AUC по дням». Эти метрики выбраны потому, что precision занижена из-за неполной разметки.

Цвета графика заданы константами `BLUE`, `TEXT_SECONDARY`, `GRID` в модуле.

## ComparisonReport.__init__  [40f7da48]
Принимает любую последовательность `ModelResult` и сохраняет её копией списка в `self.results`. Порядок не важен: таблица сортируется сама.

```python
ComparisonReport(results).results[0].name   # 'transformer' и т. д.
```

## ComparisonReport.table  [1d6d437e]
Возвращает `DataFrame`: одна строка на модель, индекс — «модель» (читаемое название), столбцы — все метрики `Score.as_dict()` плюс «ROC-AUC по дням» и время обучения. Строки отсортированы по F1 по убыванию — лучшая модель сверху.

Пример из `results/ml_freq/comparison_merged` (по F1): Случайный лес 0,476; Extra Trees 0,476; Градиентный бустинг 0,464; Transformer 0,344; Логистическая регрессия 0,290. По ROC-AUC по дням: деревья около 0,92, Transformer 0,83, логистическая регрессия 0,86. ROC-AUC оценивает вероятности до декодирования, F1 — уже готовые интервалы, поэтому по ним удобно отличать «плохая модель» от «плохо подобранный порог декодера».

## ComparisonReport.to_text  [bb2bf05c]
Строка для консоли: таблица только по `KEY_METRICS` и F1, числа с двумя знаками. Так выглядит вывод после `compare` (числа из `comparison.xlsx` для merged-набора):

```
                            найдено размеченных (recall)  начало: точно  начало: ±3 дн  конец: точно  конец: ±7 дн  ROC-AUC по дням    F1
Случайный лес                                       0.61           0.14           0.78          0.12          0.68             0.92  0.48
```

## ComparisonReport.save  [9a97832f]
Принимает папку `out_dir` (создаётся при необходимости) и пишет:

- `comparison.xlsx`: лист «Сравнение» — `table()`; затем по листу на каждую модель (имя листа — `result.name`, не длиннее 31 символа — ограничение Excel) со строками предсказаний «метка — найдено»;
- `comparison.png` — график `_plot`.

Если `--out-dir` не задан, `cli.run_compare` создаёт папку `results/ml_freq/<дд-мм-гггг_чч-мм-сс>`. В `.vscode/launch.json` отладочный запуск пишет в `results/ml_freq/debug/compare`.

```bash
.venv/Scripts/python -m gtm_detector.ml_freq compare --models gboost --out-dir results/ml_freq/debug/compare
```

В файле, как в `comparison_merged`: листы `Сравнение`, `transformer`, `logreg`, `random_forest`, `extra_trees`, `gboost`; на каждом из пяти листов моделей по 135 строк (число размеченных мероприятий).

## ComparisonReport._plot  [b3d0edae]
Рисует сетку 2×3: по одной панели на каждую из шести `KEY_METRICS`, на панели — горизонтальные столбцы по моделям, подписи в процентах. Пропуски (`nan`, например нет ошибок окончания) рисуются как 0. Ось X общая, 0…1,12, с запасом под подпись. Бэкенд `Agg` включается внутри функции, чтобы график строился без окна — в консоли и в тестах. После сохранения (110 dpi) фигура закрывается, иначе память утекала бы при многократных запусках.

Порядок моделей на графике такой же, как в `table()`, то есть по F1.
