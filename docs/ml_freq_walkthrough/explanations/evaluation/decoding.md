## @module  [1fe2b240]
Модуль содержит единственный класс `SegmentDecoder` — последний шаг между моделью и технологом. Любая модель (Transformer, `gboost`, `logreg` …) выдаёт одно и то же: массив вероятностей по дням. Декодер превращает его в интервалы `Interval(start, end)`.

Декодер **общий для всех моделей** и настраивается только через `DecoderConfig` в `config.py`. Если бы у каждой модели были свои пороги, разница в метриках отражала бы разницу в порогах, а не в качестве моделей. Поэтому `CrossValidator` (сравнение) и `run_predict` в `cli.py` (боевой запуск) используют один и тот же класс с теми же настройками.

## SegmentDecoder  [ba2b646a]
Правила декодирования, по порядку:

1. Вероятности сглаживаются скользящим средним по `smooth_days` = 5 дням (окно по центру).
2. День считается «в эффекте», если сглаженная вероятность **строго больше** `threshold` = 0,5.
3. Подряд идущие такие дни образуют период; два периода, между которыми не больше `max_gap` = 3 дней, склеиваются.
4. Периоды короче `min_length` = 2 дней выбрасываются.
5. Если период дошёл до **последнего дня данных**, его окончание неизвестно: `end=None` («эффект продолжается»).

Зачем каждый шаг: сглаживание убирает единичные скачки вероятности; склейка нужна, потому что в середине настоящего эффекта частота или дебит иногда «проваливаются» на пару дней; минимальная длина отсекает шум; `end=None` соответствует строкам разметки «ПРОДОЛЖАЕТСЯ ЭФФЕКТ».

### Пример
Скважина с рядом на 30 дней с 01.08.2023. Модель уверена (0,9) в днях 10–19, но в день 14 дала 0, и ещё есть короткий всплеск в днях 25–26:

```python
from datetime import date, timedelta
import numpy as np
from gtm_detector.ml_freq.evaluation import SegmentDecoder

dates = [date(2023, 8, 1) + timedelta(i) for i in range(30)]
proba = np.zeros(30)
proba[10:20] = 0.9
proba[14] = 0.0
proba[25:27] = 0.9
SegmentDecoder().decode(proba, dates)
# [Interval(start=2023-08-11, end=2023-08-20)]
```

Провал в день 14 «залечило» сглаживание, а всплеск из двух дней после сглаживания даёт не больше 0,36 < 0,5 и до порога не доходит. Если же вероятность высока от 23.08 до конца данных (`proba[22:] = 0.9`), результат — `Interval(start=2023-08-23, end=None)`.

## SegmentDecoder.__init__  [4cf4c5e7]
Принимает `DecoderConfig` или `None`; при `None` берутся значения по умолчанию (`threshold=0.5`, `smooth_days=5`, `max_gap=3`, `min_length=2`). Конфиг сохраняется в `self.config`.

`CrossValidator` передаёт сюда `ExperimentConfig.decoder`, поэтому при сравнении и при `predict` значения совпадают.

```python
SegmentDecoder().config.smooth_days   # 5
SegmentDecoder(DecoderConfig(threshold=0.7)).config.threshold   # 0.7
```

## SegmentDecoder.decode  [4032ce25]
Главный метод. Принимает `proba` — массив `float` длины N (вероятность эффекта по каждому дню, 0…1) и `dates` — N дат тех же дней. Возвращает список `Interval` в хронологическом порядке; `end=None`, если период доходит до последнего дня.

Окно сглаживания центрированное и с `min_periods=1`, поэтому на краях ряда оно просто короче и данные не теряются. Условие «до конца данных» проверяется по индексу последнего дня (`end == len(proba) - 1`), а не по дате. Фильтр `min_length` применяется **после** склейки, чтобы две короткие части одного эффекта не были отброшены порознь.

Пример из `run_predict`: на скважине с моделью `gboost` декодер выдаёт строки для `events_gboost.xlsx` — столбцы «начало эффекта», «окончание эффекта», «статус». Для интервала с `end=None` в «статус» пишется «эффект продолжается».

```python
SegmentDecoder().decode(np.zeros(30), dates)   # [] — эффектов нет
```

## SegmentDecoder._runs  [337a5fc2]
Служебный статический метод: из булева массива `active` находит непрерывные отрезки `True` и возвращает пары `(первый_индекс, последний_индекс)` включительно. Приём: к массиву с обеих сторон добавляются нули, берётся разность `np.diff`; +1 — начало отрезка, −1 — позиция сразу после его конца.

```python
SegmentDecoder._runs(np.array([0, 1, 1, 0, 1, 1, 1, 0, 1], bool))
# [(1, 2), (4, 6), (8, 8)]
```

## SegmentDecoder._merge  [91bb4627]
Склеивает соседние отрезки из `_runs`, если дней между ними (между концом предыдущего и началом следующего) не больше `max_gap`. Принимает список пар индексов и `max_gap` (дни), возвращает новый список.

Расстояние считается как `begin − prev_end − 1`: количество дней в разрыве. Для `max_gap=3` разрыв из трёх дней склеивается, из четырёх — нет.

```python
SegmentDecoder._merge([(2, 3), (5, 8), (20, 22)], 3)
# [(2, 8), (20, 22)]   — разрыв в 1 день склеен, разрыв в 11 дней нет
```
