## @module  [4f32a87a]
Собственная модель проекта: Transformer-энкодер для суточных рядов скважины на PyTorch. Схема:

```
15 каналов дня ─► Conv1d (ступеньки за несколько дней) ─► + позиционное кодирование
              ─► 2 × TransformerEncoderLayer (внимание по всему ряду)
              ─► LayerNorm + Linear ─► логит «день внутри эффекта»
```

Свёртка ловит форму скачка частоты и отклика дебита за несколько дней, внимание связывает скачок с окончанием эффекта через недели. Модель **двунаправленная** (каждый день видит и прошлое, и будущее): детекция офлайн, весь ряд известен.

Размеры модели задаёт `TransformerConfig`: `d_model=32`, 4 головы, 2 слоя, `dim_feedforward=64`, `dropout=0.2`, ядро свёртки 5 — всего **19 617 параметров**. Это намеренно мало: на ~100 обучающих скважинах крупная модель переобучается (при `d_model=64` и 3 слоях точное попадание в день начала 16 % против 24 %). Обучение задаёт `TrainingConfig`: 80 эпох, батч 16, AdamW (`lr=1e-3`, `weight_decay=1e-4`), окна по 128 дней, 4 окна на скважину.

Результат в сравнении `compare` (данные 2021–2026): полнота 0,481, точность 0,267, начало ±3 дня 0,831 (лучшее из всех моделей), но окончание ±7 дней 0,362 и ROC-AUC 0,831 — хуже деревьев (Extra Trees: 0,662 и 0,920). Обучение на 5 фолдах — 1522 с на процессоре против 35–112 с у scikit-learn. Для Transformer разброс между зёрнами случайности сравним с эффектом, поэтому выводы «лучше/хуже» делаются по нескольким зёрнам.

## PositionalEncoding  [27a38aa5]
Модуль PyTorch: добавляет к каждому дню синусоидальный «номер позиции» (Vaswani et al., 2017). Без него внимание не отличало бы порядок дней: ряд из тех же значений в перемешанном порядке выглядел бы так же.

Вход и выход — тензор `(batch, дни, d_model)`; таблица кодирования не обучается и не сохраняется в весах (`persistent=False`) — её можно пересчитать.

### Пример
При `d_model=32`, `max_length=4096` в таблице 4096 × 32 чисел. Сумма для окна из 128 дней: `x + encoding[:128]`.

## PositionalEncoding.__init__  [2a7df33c]
Строит таблицу `encoding` формы `(max_length, d_model)`: чётные столбцы — `sin(pos · k)`, нечётные — `cos(pos · k)` с частотами `k = exp(−ln(10000) · i / d_model)`. Параметры: `d_model` — размерность скрытого слоя (32), `max_length` — максимальная длина ряда (4096 дней, ≈11 лет; самая длинная скважина данных — 2257 дней).

### Пример
```python
pe = PositionalEncoding(32, 4096)
pe.encoding.shape      # torch.Size([4096, 32])
```

## PositionalEncoding.forward  [bf634b32]
Принимает `x` формы `(batch, L, d_model)` и возвращает `x + encoding[:L]` — таблица подрезается по длине ряда и складывается с признаками по всем сериям батча (broadcast). Если `L > max_length`, возникнет ошибка формы: ряды длиннее 4096 дней в `predict_proba` не поддерживаются.

### Пример
```python
x = torch.zeros(2, 100, 32)
pe(x).shape            # torch.Size([2, 100, 32])
```

## TimeSeriesTransformer  [18f917af]
Сама нейросеть: `(batch, дни, каналы) → (batch, дни)` логитов. Состав:

1. `embed` — `Conv1d(15 → 32, kernel=5, padding=2)`: превращает 15 каналов дня в 32 скрытых признака, учитывая ±2 соседних дня; `padding=2` сохраняет длину ряда;
2. `position` — `PositionalEncoding`;
3. `encoder` — 2 слоя `TransformerEncoderLayer` с 4 головами, `norm_first=True` (нормализация до внимания — стабильнее на маленьких данных), `dropout=0,2`;
4. `head` — `LayerNorm` + `Linear(32 → 1)`: по одному числу на день.

Выход — **логиты**, а не вероятности: функция потерь `BCEWithLogitsLoss` численно устойчивее, а в `predict_proba` логит превращается в вероятность сигмоидой.

### Пример
```python
net = TimeSeriesTransformer(15, TransformerConfig())
sum(p.numel() for p in net.parameters())     # 19617
net(torch.zeros(2, 100, 15)).shape           # torch.Size([2, 100])
```
Это проверяет `test_transformer_forward_shape`.

## TimeSeriesTransformer.__init__  [54ae65c9]
Собирает слои. Параметры: `n_channels` — число входных каналов (`FeatureBuilder.sequence_size` = 15), `config` — `TransformerConfig` (`d_model`, `n_heads`, `n_layers`, `dim_feedforward`, `dropout`, `conv_kernel`, `max_length`). Число каналов передаётся отдельно, чтобы размер входа нельзя было рассинхронизировать с признаками. `enable_nested_tensor=False` отключает оптимизацию PyTorch, которая плохо сочетается с маской паддинга.

### Пример
```python
TimeSeriesTransformer(15, TransformerConfig(d_model=64, n_layers=3, dim_feedforward=128))
```
Этот вариант (крупнее) на данных проекта работал хуже, чем 32 / 2 слоя.

## TimeSeriesTransformer.forward  [58013849]
Прямой проход. Параметры: `x` — `(batch, L, 15)`, `float32`; `padding_mask` — булев `(batch, L)`, `True` там, где данных нет (хвост короткого окна, добитый нулями), либо `None`. Шаги: `x.transpose(1, 2)` (Conv1d ждёт `(batch, каналы, дни)`) → свёртка → обратно `(batch, L, 32)` → позиционное кодирование → энкодер (внимание игнорирует позиции паддинга) → голова → `squeeze(-1)`. Возвращает `(batch, L)` логитов.

### Пример
Скважина из 1587 дней: `net(x)` с `x.shape == (1, 1587, 15)` даёт `(1, 1587)` без маски; при обучении батч из окон разной длины идёт с `padding_mask`.

## TransformerSegmenter  [aa918a78]
Обёртка сети в интерфейс `EventSegmenter`: готовит признаки и окна, обучает, предсказывает, сохраняет. Атрибуты: `name = "transformer"`, `title = "Transformer (своя модель, PyTorch)"`, `config` (архитектура), `training` (параметры обучения), `network` — сеть или `None` до `fit`.

### Пример

```python
model.fit(train_wells)                   # network обучена, переведена в eval()
```

## TransformerSegmenter.fit  [97625e2b]
Обучает сеть на размеченных скважинах. Последовательность:

1. Зерно: `torch.manual_seed(seed)` и `np.random.default_rng(seed)` — воспроизводимость.
2. Для каждой скважины: `sequence()` (L × 15), `target()` (0/1) и `training_mask(45)`.
3. Вес положительного класса `pos_weight = отрицательные / положительные` по дням внутри масок. На всех размеченных скважинах: 14 247 дней в маске, 5 213 положительных, значит `pos_weight ≈ 1,73`. Почему так: эффект занимает меньшую часть окна, без веса сеть предпочла бы всегда отвечать «нет».
4. Сеть, AdamW и `CosineAnnealingLR` (скорость обучения плавно падает по косинусу за 80 эпох).
5. Каждую эпоху `_sample_crops` заново нарезает окна, они перемешиваются, батчи по 16 собираются `_collate`. Потеря = сумма `BCE × weight` / сумма весов, то есть **считается только по дням маски обучения**; дни после `censored`-мероприятий и дни вне окрестности размеченных событий в потери не входят, хотя сеть их «видит» как контекст.
6. Обрезка градиента (норма ≤ 1) стабилизирует обучение на маленьких батчах.
7. В конце `network.eval()` — отключается dropout.

Возвращает `self`. Каждые 20 эпох пишет в журнал `logger.debug` суммарную потерю.

### Пример
Фолд из ~100 обучающих скважин с разметкой: 4 окна на скважину → ~400 окон за эпоху → 25 батчей по 16, 80 эпох ≈ 2000 шагов оптимизатора. На 5 фолдах — 1522 с на процессоре. Тест `test_transformer_fit_predict_save_load` проверяет цикл на 8 синтетических скважинах из `conftest.py`.

## TransformerSegmenter.predict_proba  [c125c843]
Вероятность «день внутри эффекта» для каждого дня одной скважины. Весь ряд (L × 15) подаётся в сеть **целиком** одним батчем (`unsqueeze(0)` → `(1, L, 15)`), без нарезки на окна и без паддинга, потом `sigmoid` и `squeeze` дают массив `(L,)`. Целиком, потому что на обучении окна были лишь аугментацией, а в применении нужен контекст всего ряда. Работает под `torch.no_grad()`. Не обучена — `RuntimeError("Transformer не обучен")`.

### Пример
```python
p = model.predict_proba(well)      # скважина 8822: p.shape == (1587,)
```
Дальше `SegmentDecoder` сглаживает `p` окном в 5 дней и режет по порогу 0,5.

## TransformerSegmenter.load  [525a3096]
Классовый метод: читает `.pt` (`weights_only=True` — безопасная загрузка без исполнения кода, `map_location="cpu"`), создаёт модель по сохранённым настройкам, сверяет список каналов и загружает веса. Если `SEQUENCE_CHANNELS` с тех пор изменились, выбрасывает `ValueError("Набор признаков изменился — переобучите модель")`: без проверки сеть получила бы данные «не в тех столбцах» и ошибалась бы молча. После загрузки — `eval()`.

### Пример
```python

```

## TransformerSegmenter._sample_crops  [75c819b0]
Нарезает случайные окна для одной эпохи. Для каждой скважины с непустой маской обучения делает `crops_per_well` = 4 окон длиной `crop_length` = 128 дней. Центр окна — случайный день **из маски**, поэтому окна не тратятся на скважины и участки без размеченных событий. Начало окна обрезается в границы ряда (`clip(0, L − 128)`); если ряд короче 128 дней, окно короче.

Возвращает список троек `(признаки (≤128, 15), цель, маска)`. Окна каждый раз новые — это аугментация: одно и то же мероприятие оказывается в разных местах окна. Скважины без разметки пропускаются целиком.

### Пример
Для 8 синтетических скважин из `tests/conftest.py` (по 120 дней, одно событие) получается 8 × 4 = 32 окна формы `(120, 15)`: ряд короче `crop_length`, окно покрывает его целиком. Скважина без разметки (`make_well(step=None)`) даёт 0 окон. На скважине 8822 (1587 дней) окно длиной 128 примерно совпадает по размеру с маской (128 дней).

## TransformerSegmenter._collate  [2681c037]
Склеивает окна в батч, дополняя короткие нулями до самого длинного. Возвращает четыре тензора:

| Тензор | Форма | Смысл |
|--------|-------|-------|
| `x` | `(batch, L, 15)` | признаки, нули в паддинге |
| `y` | `(batch, L)` | цель 0/1 |
| `padding` | `(batch, L)`, bool | `True` — позиция добавлена паддингом, внимание её игнорирует |
| `weight` | `(batch, L)` | 1 — день входит в маску обучения (и в потери), 0 — нет, в том числе в паддинге |

Две разные маски нужны потому, что «нет данных» (паддинг) и «данные есть, но учиться на них нельзя» (вне окрестности событий) — разные вещи: первое убирается из внимания, второе — из функции потерь.

### Пример
```python
x, y, padding, weight = TransformerSegmenter._collate(crops[:4])
x.shape                # torch.Size([4, 120, 15])
weight.sum(dim=1)      # tensor([102., 102., 102., 102.]): 102 из 120 дней в маске
```
Окно из 50 дней рядом с окном из 120: `padding.sum(1) == [70, 0]` — у короткого 70 позиций паддинга.
