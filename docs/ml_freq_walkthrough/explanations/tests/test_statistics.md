## @module  [27be2ca9]
Тесты чтения полугодовых файлов статистики (`data/statistics.py`): достать поток книги из `.xls`, разобрать лист в таблицу, склеить периоды и убедиться, что пустая папка не проходит молча. Настоящие файлы `resources/statistics/*/*.xls` тяжёлые (около трёх минут на чтение), поэтому тесты строят минимальные: файл OLE2 в несколько секторов и «лист» с интерфейсом `xlrd`. Запуск:

```bash
.venv/Scripts/python -m pytest gtm_detector/ml_freq/tests/test_statistics.py -q
```

## _ole_file  [faa98476]
Вспомогательная функция, не тест. Собирает в памяти минимальный файл формата OLE2 (старый `.xls`): заголовок 512 байт, сектор таблицы размещения (FAT), сектор каталога с одной записью `Workbook` и сам поток. Параметр `declared` — размер потока, **записанный в каталоге**; поток при этом может быть длиннее. Именно такое расхождение есть в настоящих выгрузках, из-за чего `xlrd` отказывается их открывать.

### Пример
`_ole_file(bytes(range(256)) * 6, declared=513)` — поток из 1536 байт (3 сектора), в каталоге записано 513 байт (чуть больше одного сектора).

## test_workbook_stream_follows_chain_longer_than_declared  [b1ea41da]
**Что проверяет.** `_workbook_stream` идёт по цепочке секторов до конца, а не обрезает поток по размеру из каталога.

**Данные.** Поток 3 сектора, в каталоге указан размер `SECTOR + 1` = 513 байт.

**Результат.** Функция возвращает ровно исходные 1536 байт.

**Какую ошибку поймал бы.** Если бы читатель доверял размеру из каталога (как делает `xlrd`), книга обрезалась бы, и вместо данных за полугодие читались бы обрывки, либо снова появилось бы «size exceeds expected».

## _Sheet  [ed3c1a9a]
Тестовый двойник листа `xlrd`: хранит строки значений и отдаёт их так же, как настоящий лист. Нужен, чтобы проверять `_sheet_table` без файла.

### Пример
`_Sheet([["Версия", ""], ["№ скв.", "01.01.2021"]]).nrows == 2`.

## _Sheet.row_values  [74c9d94d]
Значения строки по номеру: как `sheet.row_values(r)` в `xlrd`.

`sheet.row_values(1)[2] == "01.01.2021"` — заголовок с датой.

## _Sheet.row_types  [b4a2c431]
Типы ячеек строки: `float` -> `XL_CELL_NUMBER`, `str` -> `XL_CELL_TEXT`, пустая строка -> `XL_CELL_EMPTY`. Так `_sheet_table` отличает число от текста и от пустой ячейки.

### Пример
Для строки `["101", "5А", 48.0, "ремонт"]` типы: текст, текст, число, текст.

## _sheet  [54f742d3]
Строит тестовый лист в раскладке выгрузки: строка 0 — версия, строка 1 — заголовок («№ скв.», «№ куста» и две даты `first`, `second`), строка 2 — пустая, далее скважины `wells`. Ровно как в настоящих файлах: данные с третьей строки.

### Пример
`_sheet("01.01.2021", "02.01.2021", [["101", "5А", 48.0, "ремонт"]])`.

## test_sheet_table_keeps_only_numbers  [1401a1a1]
**Что проверяет.** `_sheet_table` оставляет только числа, пропускает строки без номера скважины и повторы, считает нечисловые ячейки.

**Данные.** Две даты, 01.01.2021 и 02.01.2021, и четыре строки:

| Строка | Что в ней | Ожидание |
|--------|-----------|----------|
| `101 / 5А: 48.0, «ремонт»` | число и текст | 48.0 и `NaN`; текст считается в `bad` |
| без номера: `1.0, 2.0` | итоги листа | строка пропущена |
| `101 / 5А: 7.0, 7.0` | повтор скважины | игнорируется, верна первая строка |
| `202.0 / 6: пусто, 50.0` | номер числом, пустая ячейка | скважина «202»: `NaN` и 50.0 |

**Результат.** Индекс `[("101", "5А"), ("202", "6")]`, счётчик нечисловых `bad == [0, 1]` (текст «ремонт» считается, пустая ячейка — нет), первый столбец — `2021-01-01`.

**Какую ошибку поймал бы.** Строка итогов, попавшая в таблицу как «скважина»; число, превращённое в текст; пустая ячейка, посчитанная как мусор (аудит показывал бы тысячи ложных «не чисел»).

## test_join_periods_makes_continuous_calendar  [368cf507]
**Что проверяет.** `_join_periods` строит непрерывный календарь и объединяет скважины.

**Данные.** Первый файл: скважина 101/5 за 29.06 и 30.06.2021. Второй: 101/5 и новая 202/6 за 02.07.2021. Дня 01.07 нет ни в одном файле.

**Результат.** Четыре столбца с 29.06 по 02.07; у 101/5 значения 1, 2, `NaN` (01.07), 3; у 202/6 — `NaN` везде, кроме 02.07 (4.0).

**Какую ошибку поймал бы.** Если бы пропущенный день исчез из столбцов, окна «30 дней назад» в `FeatureBuilder` считали бы 30.06 и 02.07 соседними днями; потерянная новая скважина означала бы, что часть разметки «нет в статистике».

## test_reader_requires_files  [52a6ba8d]
