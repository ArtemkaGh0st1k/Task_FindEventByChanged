## test_target_and_training_mask  [91a56e79]
**Что проверяет.** Как размеченный интервал превращается в целевой вектор по дням и в маску дней, на которых разрешено учиться.

**Данные.** `make_well(step=40, effect=30)`: ряд 120 дней, частота поднята в день 40, эффект — дни 42–71 (12.02–13.03.2026).

**Проверки:**

- `target.sum() == 30`, `target[42] == 1`, `target[41] == 0` — единицы ровно на дни эффекта, включая оба конца;
- `training_mask(context_days=10)`: `mask[32]` истинно, `mask[31]` ложно — 10 дней контекста до начала (42 − 10 = 32); `mask[81]` истинно, `mask[82]` ложно — 10 дней после окончания (71 + 10 = 81). Всего в маске 50 дней: 10 + 30 + 10;
- `training_mask(None).all()` — без ограничения обучаются все дни.

**Какую ошибку поймал бы.** Сдвиг границ на день (`<` вместо `<=`), неверный отсчёт контекста: модель начала бы учиться на днях, где разметке верить нельзя (в разметке есть не все реальные подъёмы), или потеряла бы день начала. Ошибка в маске — нарушение правила «обучаться только на `training_mask`».

```bash
.venv/Scripts/python -m pytest gtm_detector/ml_freq/tests/test_data_and_features.py::test_target_and_training_mask -q
```

## test_features_shapes_and_values  [a175b789]
**Что проверяет.** Форму и разумность признаков `FeatureBuilder` и то, что в них видно событие.

**Данные.** `make_well()`: частота 48 → 50 Гц в день 40, дебит жидкости 100 → 110 в дни 42–71.

**Проверки:**

- `sequence` имеет форму `(120, 15)` (15 каналов `SEQUENCE_CHANNELS`), `tabular` — `(120, 106)` (по числу `tabular_names`);
- в табличных признаках нет `NaN`, а модуль значений не больше 3 (константа `CLIP`);
- канал `f_diff` в день 40 положителен (в тесте 0,4: скачок на 2 Гц при опорной частоте около 50 Гц, умноженный на 10);
- канал `liq_vs_step` в день 45 больше 0,05 (в тесте 0,094): дебит жидкости выше уровня до скачка примерно на 10 %.

**Какую ошибку поймал бы.** Добавленный канал без правки `SEQUENCE_CHANNELS` (форма не совпадёт), `NaN` из-за деления на ноль или пропусков, потерю обрезки значений, перепутанный знак разности, сдвиг каналов «от скачка» на день. Если канал добавлен намеренно, тест надо обновить вместе с README и помнить, что старые веса `.pt` перестанут загружаться.

```bash
.venv/Scripts/python -m pytest gtm_detector/ml_freq/tests/test_data_and_features.py::test_features_shapes_and_values -q
```

## test_parsing_helpers  [383bf2da]
**Что проверяет.** Функции чтения «грязных» данных из `data/readers.py`, которые применяются и к разметке, и к статистике.

**Данные.** Реальные виды опечаток из Excel:

| Вход | Результат | Зачем |
|------|-----------|-------|
| `" 561E "` | `"561Е"` | пробелы убраны, латинская `E` заменена кириллической `Е` |
| `7782.0` | `"7782"` | номер скважины, прочитанный как float, без `.0` |
| `"21.04.2026г"` | `date(2026, 4, 21)` | лишняя буква после года |
| `"08.02.206"` | `date(2026, 2, 8)` | пропущена цифра в году (206 → 2026) |
| `"нет"` | `None` | не дата |

**Какую ошибку поймал бы.** Номера скважин из статистики и разметки перестали бы совпадать (латиница и кириллица в «561E» выглядят одинаково), и мероприятия молча «потерялись» бы; даты с опечатками превратились бы в `None` или в дату из 206 года.

```bash
.venv/Scripts/python -m pytest gtm_detector/ml_freq/tests/test_data_and_features.py::test_parsing_helpers -q
```
