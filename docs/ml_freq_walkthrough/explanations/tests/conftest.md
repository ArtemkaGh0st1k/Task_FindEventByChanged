## @module  [50fe72b5]
Общие заготовки для всех тестов: **синтетические скважины** с заранее известными датами подъёма частоты и эффекта. Реальные Excel-файлы в тестах не читаются, поэтому весь набор (14 тестов) проходит за десятки секунд, а ожидаемый ответ известен до запуска.

Файл `conftest.py` pytest подхватывает сам: фикстура `wells` доступна в любом тесте по имени аргумента, а `make_well` и `day` тесты импортируют явно (`from gtm_detector.ml_freq.tests.conftest import day, make_well`).

В цепочке «Excel → скважины → признаки → модель → интервалы» синтетическая скважина заменяет первые два шага: сразу получается готовый `WellSeries` с таблицей `frame` и разметкой `labels`.

## day  [7117beaa]
Дата по номеру дня от начала календаря: `day(0)` — 1 января 2026 (константа `START`). Тесты записывают даты как числа, а в проверках переводят их в `date`.

### Пример
```python
day(0)    # date(2026, 1, 1)
day(40)   # date(2026, 2, 10)  - день подъёма частоты в make_well() по умолчанию
day(42)   # date(2026, 2, 12)  - начало эффекта в разметке
```

## make_well  [ca1ccdd9]
Собирает одну синтетическую скважину `WellSeries` с одним подъёмом частоты и одним периодом эффекта.

Параметры:

| Параметр | По умолчанию | Смысл |
|----------|--------------|-------|
| `n_days` | 120 | длина ряда, дней |
| `step` | 40 | номер дня, когда частота поднимается; `None` — подъёма нет, разметки нет |
| `effect` | 30 | сколько дней дебит жидкости остаётся повышенным |
| `seed` | 0 | зерно шума; номер скважины получается `W<seed>` |

Что внутри (для значений по умолчанию):

- `frequency` = 48 Гц, с дня `step` (40-й, 10.02.2026) — 50 Гц;
- `debit_liquid` = 100 м³/сут, а в дни `step+2 … step+1+effect` (42–71-й) равен 110, плюс шум N(0; 0,3) из `np.random.default_rng(seed)`. Эффект запаздывает на 2 дня после подъёма частоты, как и в реальных данных;
- `debit_oil` = 0,1 от дебита жидкости **без шума** (10, в эффекте 11), `watercut` = 90 %, `pressure_zab` = 50, `pressure_line` = 12, `state` = 1 (насос работает);
- разметка — один `Interval(start=day(step+2), end=day(step+1+effect), date_done=day(step))`: то есть 12.02.2026 — 13.03.2026, «дата выполнения» 10.02.2026.

Зерно случайности передаётся в `default_rng`, а не в глобальный `np.random` — правило проекта о воспроизводимости.

### Пример
```python
well = make_well()
well.frame.iloc[[0, 39, 40, 42, 71, 72]][["frequency", "debit_liquid", "debit_oil"]].round(2)
#             frequency  debit_liquid  debit_oil
# 2026-01-01       48.0        100.04       10.0
# 2026-02-09       48.0        100.45       10.0
# 2026-02-10       50.0         99.62       10.0   <- подъём частоты, дебит ещё прежний
# 2026-02-12       50.0        110.40       11.0   <- начало эффекта (разметка)
# 2026-03-13       50.0        110.21       11.0   <- конец эффекта (разметка)
# 2026-03-14       50.0        100.30       10.0   <- возврат к базе
len(well), well.number      # (120, 'W0')
well.labels                 # [Interval(start=2026-02-12, end=2026-03-13, date_done=2026-02-10)]
```

`make_well(step=None)` даёт скважину без события: частота 48 весь период, `labels == []`.

## wells  [121318ae]
Фикстура pytest: **восемь скважин** `W0 … W7` для тестов моделей. Скважина `i` создаётся как `make_well(step=30+3*i, effect=25+2*i, seed=i)`: подъёмы и длины эффекта у всех разные, чтобы модели не могли выучить одну дату, а шум отличался.

| Скважина | Подъём частоты (день) | Эффект с — по |
|----------|----------------------|---------------|
| W0 | 30 | 02.02.2026 — 26.02.2026 |
| W1 | 33 | 05.02.2026 — 03.03.2026 |
| W3 | 39 | 11.02.2026 — 13.03.2026 |
| W7 | 51 | 23.02.2026 — 02.04.2026 |

Восьми хватает для `ExperimentConfig(folds=2)`: в каждом фолде по четыре скважины, у каждой ровно одно размеченное мероприятие, поэтому тест перекрёстной проверки может сверить `TP + FN == 8`.

### Пример
```python
def test_something(wells):          # pytest подставит список из 8 скважин
    assert len(wells) == 8 and wells[3].number == "W3"
```
