# Локальные агенты Claude Code для проекта

Инструкция: как устроены проектные агенты (субагенты) Claude Code, какие агенты
уже настроены для `Task_FindEventByChanged` и как с ними работать.

## 1. Что такое локальный агент

Субагент — отдельный «специалист» со своим системным промптом, набором инструментов
и моделью. Главная сессия Claude Code передаёт ему задачу, он работает в **своём
контексте** и возвращает только итог. Это:

- держит основной диалог чистым (логи обучения, длинные отчёты остаются у агента);
- закрепляет роль и правила (PyTorch, PEP 8, методика экспериментов) — не нужно
  повторять их в каждом запросе;
- ограничивает права (ревьюер не может править код, экспериментатор — тоже).

## 2. Где лежат агенты

| Уровень | Путь | Видимость |
|---------|------|-----------|
| **Проект** | `<корень проекта>/.claude/agents/*.md` | только в этом проекте; коммитится в git — общий для команды |
| Пользователь | `~/.claude/agents/*.md` (Windows: `C:\Users\<имя>\.claude\agents\`) | во всех проектах |

При совпадении имён побеждает агент проекта. Для «агента именно на текущий проект»
нужен первый вариант — он и использован здесь.

Дополнительно Claude Code автоматически читает **`CLAUDE.md`** в корне проекта —
это общая «память» проекта: команды, стиль, правила. Агенты получают её тоже,
поэтому общие правила лежат там, а в файлах агентов — только специфика роли.

## 3. Формат файла агента

```markdown
---
name: ml-engineer                 # уникальное имя: строчные буквы и дефисы
description: Когда звать агента.  # по этому тексту Claude решает, делегировать ли задачу
tools: Read, Edit, Write, Bash    # необязательно; без поля — все инструменты сессии
model: inherit                    # sonnet | opus | haiku | inherit (как у основной сессии)
color: blue                       # необязательно: цвет в интерфейсе
---

Системный промпт агента: роль, контекст, правила, процесс, формат отчёта.
```

Советы по написанию:

- **`description` — самое важное поле.** Пишите, *когда* применять агента, конкретными
  словами задачи. Фраза «Используй ПРОАКТИВНО после …» заставляет Claude звать агента сам.
- Давайте минимально нужные `tools`: аналитику и ревьюеру — без `Edit`/`Write`.
- В тело — то, что агент не узнает из кода: цели, бейзлайны, подводные камни данных,
  критерий «готово», формат ответа.
- Для рутинных задач (прогон экспериментов, тесты) — `model: sonnet` (быстрее и дешевле),
  для проектирования моделей — `inherit`/`opus`.

## 4. Как создать агента

**Вариант А — командой.** В интерактивном терминале `claude` в корне проекта:
`/agents` → *Create new agent* → *Project* → описать роль (Claude сгенерирует черновик) →
выбрать инструменты и модель → сохранить. Файл появится в `.claude/agents/`.

**Вариант Б — вручную.** Создать файл `.claude/agents/<имя>.md` в формате выше.
Агент подхватывается в новой сессии (или после `/agents`).

Проверить список: `/agents` в терминале `claude`.

## 5. Агенты этого проекта

| Агент | Роль | Права | Модель |
|-------|------|-------|--------|
| [`ml-engineer`](../.claude/agents/ml-engineer.md) | senior ML-инженер: модели PyTorch/sklearn, признаки, обучение, декодер | чтение + правка + Bash | inherit |
| [`data-auditor`](../.claude/agents/data-auditor.md) | качество данных 2021–2026, сдвиг 180 дней, утечки, потери разметки | чтение + правка `data/` | inherit |
| [`experiment-runner`](../.claude/agents/experiment-runner.md) | запуск `compare/train/predict`, статистика по seed, анализ ошибок | только чтение + Bash | sonnet |
| [`ml-code-reviewer`](../.claude/agents/ml-code-reviewer.md) | ревью: PEP 8 (ruff), тесты, ML-ошибки | только чтение + Bash | inherit |
| [`test-engineer`](../.claude/agents/test-engineer.md) | pytest на синтетических скважинах | чтение + правка + Bash | sonnet |

Общие для всех файлы:

- [`CLAUDE.md`](../CLAUDE.md) — задача, структура, команды, стиль, правила ML, подводные камни данных;
- [`pyproject.toml`](../pyproject.toml) — настройки `ruff` (PEP 8, строка ≤ 99) и `pytest`.

## 6. Как пользоваться

Claude сам выбирает агента по `description`, но надёжнее назвать его явно:

```text
Используй агента ml-engineer: добавь в Transformer отдельную голову для даты окончания эффекта.
Попроси data-auditor выяснить, сколько мероприятий 2025 года можно вернуть в обучение.
Пусть experiment-runner сравнит transformer на seed 0,1,2 с extra_trees.
Запусти ml-code-reviewer на текущий diff.
```

В интерфейсе также можно упомянуть агента через `@` (например, `@ml-engineer`).

### Рекомендуемый цикл улучшения модели

```
data-auditor ──► ml-engineer ──► test-engineer ──► ml-code-reviewer ──► experiment-runner
 (данные ок?)    (гипотеза+код)   (тесты)           (PEP 8, утечки)      (цифры до/после)
                      ▲                                                        │
                      └──────────── вывод: принять / отклонить ◄───────────────┘
```

1. **data-auditor** — убедиться, что данные и разметка корректны; узнать, где теряются примеры.
2. **ml-engineer** — одна гипотеза → минимальное изменение → тесты → `compare`.
3. **test-engineer** — дописать тесты, если покрытие слабое.
4. **ml-code-reviewer** — ревью diff; блокеры возвращаются к ml-engineer.
5. **experiment-runner** — независимый прогон на нескольких seed; итог в README.

Агенты запускаются параллельно, если задачи независимы (например, аудит данных и
ревью кода одновременно).

## 7. Что улучшит работу агентов дальше

- **Больше разметки** — главный рычаг: исходные полугодовые выгрузки 2021–2025 вместо
  склеенной статистики (сейчас в обучение идёт ~135 из 786 мероприятий).
- **Привести код к ruff**: 72 длинные строки и 2 сортировки импортов
  (`ruff check --fix`, затем ручной перенос строк) — отдельным коммитом, чтобы новые
  замечания были сразу видны.
- **Фиксированный «золотой» прогон**: сохранить `results/ml_freq/baseline_*` и указывать
  его в `CLAUDE.md` — агентам будет с чем сравнивать без 15-минутного пересчёта.
- **Хуки** (`.claude/settings.json`): автоматический `ruff check` после правок `.py`.
- **Обновлять `CLAUDE.md`** после каждого принятого эксперимента: новые бейзлайны,
  отклонённые идеи (чтобы агенты их не повторяли).
