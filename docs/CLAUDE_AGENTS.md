# Локальные агенты Claude Code для проекта

Как устроены агенты Claude Code, привязанные к проекту, какие агенты уже настроены
для `Task_FindEventByChanged` и как с ними работать.

## 1. Что такое локальный агент

Агент (в документации Claude Code — «субагент») — отдельный помощник со своими
инструкциями, набором инструментов и моделью. Основная сессия Claude Code передаёт ему
задачу, он работает в **собственном контексте** и возвращает только итог. Что это даёт:

- основной диалог остаётся коротким: журналы обучения и длинные отчёты остаются у агента;
- роль и правила (PyTorch, PEP 8, порядок экспериментов) закреплены — не нужно
  повторять их в каждом запросе;
- права ограничены: проверяющий и экспериментатор не могут менять код.

## 2. Где лежат агенты

| Уровень | Путь | Где доступен |
|---------|------|--------------|
| **Проект** | `<корень проекта>/.claude/agents/*.md` | только в этом проекте; хранится в git и общий для всей команды |
| Пользователь | `~/.claude/agents/*.md` (в Windows — `C:\Users\<имя>\.claude\agents\`) | во всех проектах |

Если имена совпадают, используется агент проекта. Для агента «именно на текущий проект»
нужен первый вариант — он и выбран здесь.

Кроме того, Claude Code сам читает файл **`CLAUDE.md`** в корне проекта — это общая
память проекта: команды, стиль, правила. Агенты тоже его получают, поэтому общие правила
записаны там, а в файлах агентов — только то, что относится к роли.

## 3. Формат файла агента

```markdown
---
name: ml-engineer                 # уникальное имя: строчные латинские буквы и дефисы
description: Когда вызывать агента. # по этому тексту Claude решает, передать ли агенту задачу
tools: Read, Edit, Write, Bash    # необязательно; если поля нет — доступны все инструменты сессии
model: inherit                    # sonnet | opus | haiku | inherit (та же модель, что в основной сессии)
color: blue                       # необязательно: цвет агента в интерфейсе
---

Инструкции агента: роль, контекст, правила, порядок работы, формат отчёта.
```

**Что можно писать по-русски, а что нет.** Описание (`description`) и весь текст
инструкций — на русском. Служебные поля (`name`, `tools`, `model`, `color`), их
значения, названия инструментов, команды, пути и имена из кода остаются латиницей:
так их распознаёт Claude Code и так они называются в проекте.

Советы по написанию:

- **`description` — самое важное поле.** Опишите конкретными словами, *когда* нужен
  агент. Фраза «Вызывай по собственной инициативе после …» заставляет Claude
  обращаться к агенту самостоятельно.
- Давайте только нужные инструменты: аналитику и проверяющему — без `Edit` и `Write`.
- В инструкции пишите то, чего агент не узнает из кода: цели, опорные результаты,
  подводные камни данных, когда работа считается готовой, в каком виде отчитаться.
- Для рутины (прогон экспериментов, тесты) подходит `model: sonnet` — быстрее и дешевле;
  для проектирования моделей — `inherit` или `opus`.

## 4. Как создать агента

**Способ 1 — командой.** В терминале запустите `claude` в корне проекта и выполните
`/agents` → *Create new agent* → *Project*. Опишите роль (Claude подготовит черновик),
выберите инструменты и модель, сохраните. Файл появится в `.claude/agents/`.

**Способ 2 — вручную.** Создайте файл `.claude/agents/<имя>.md` в формате выше.
Агент станет доступен в новой сессии.

Список агентов можно посмотреть командой `/agents` в терминале `claude`.

## 5. Агенты этого проекта

| Агент | Роль | Права | Модель |
|-------|------|-------|--------|
| [`ml-engineer`](../.claude/agents/ml-engineer.md) | ведущий инженер машинного обучения: модели на PyTorch и scikit-learn, признаки, обучение, декодер | читает, меняет код, запускает команды | как в сессии |
| [`data-auditor`](../.claude/agents/data-auditor.md) | качество данных 2021–2026, сдвиг на 180 дней, утечки, потери разметки | читает, меняет код в `data/`, запускает команды | как в сессии |
| [`experiment-runner`](../.claude/agents/experiment-runner.md) | запуск `compare`, `train`, `predict`, оценка разброса по зёрнам, разбор ошибок | читает и запускает команды | sonnet |
| [`ml-code-reviewer`](../.claude/agents/ml-code-reviewer.md) | проверка кода: PEP 8 (ruff), тесты, ошибки машинного обучения | читает и запускает команды | как в сессии |
| [`test-engineer`](../.claude/agents/test-engineer.md) | тесты pytest на синтетических скважинах | читает, меняет код, запускает команды | sonnet |

Общие для всех файлы:

- [`CLAUDE.md`](../CLAUDE.md) — задача, структура, команды, стиль, правила машинного
  обучения, подводные камни данных;
- [`pyproject.toml`](../pyproject.toml) — настройки `ruff` (PEP 8, строка до 99 символов)
  и `pytest`.

## 6. Как пользоваться

Claude сам выбирает агента по описанию, но надёжнее назвать агента явно:

```text
Используй агента ml-engineer: добавь в Transformer отдельный выход для даты окончания эффекта.
Попроси data-auditor выяснить, сколько мероприятий 2025 года можно вернуть в обучение.
Пусть experiment-runner сравнит transformer на зёрнах 0, 1, 2 с extra_trees.
Запусти ml-code-reviewer на текущие изменения.
```

В интерфейсе агента также можно упомянуть через `@` (например, `@ml-engineer`).

### Рекомендуемый цикл улучшения модели

```
data-auditor ──► ml-engineer ──► test-engineer ──► ml-code-reviewer ──► experiment-runner
(данные в       (гипотеза        (тесты)           (PEP 8, утечки)      (цифры до и после)
 порядке?)       и код)
                     ▲                                                          │
                     └─────────────── вывод: принять или отклонить ◄────────────┘
```

1. **data-auditor** — убедиться, что данные и разметка корректны, и узнать, где теряются примеры.
2. **ml-engineer** — одна гипотеза → минимальное изменение → тесты → `compare`.
3. **test-engineer** — дописать тесты, если их мало.
4. **ml-code-reviewer** — проверить изменения; критичные замечания возвращаются к ml-engineer.
5. **experiment-runner** — независимый прогон на нескольких зёрнах; итог — в README.

Независимые задачи можно отдать агентам одновременно (например, аудит данных и
проверку кода).

## 7. Что ещё улучшит работу агентов

- **Больше разметки** — главный способ улучшить модели: исходные полугодовые выгрузки
  2021–2025 вместо склеенной статистики (сейчас в обучение попадает около 135 из 786
  мероприятий).
- **Привести код к требованиям ruff:** 72 слишком длинные строки и 2 места с
  неотсортированными импортами (`ruff check --fix`, затем перенос строк вручную) —
  отдельным коммитом, чтобы новые замечания сразу были видны.
- **Сохранённый опорный прогон:** держать `results/ml_freq/baseline_*` и указать его в
  `CLAUDE.md`, чтобы агентам было с чем сравнивать без 15-минутного пересчёта.
- **Хуки** (`.claude/settings.json`): автоматический запуск `ruff check` после
  изменения файлов `.py`.
- **Обновлять `CLAUDE.md`** после каждого принятого эксперимента: новые опорные
  результаты и отклонённые идеи, чтобы агенты их не повторяли.
