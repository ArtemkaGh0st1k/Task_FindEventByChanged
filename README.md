# gtm_detector/ml_freq

3) ML-подход для ГТМ `увеличение частоты F`: собственная нейросеть
(Transformer-энкодер для временных рядов, PyTorch) и готовые модели
scikit-learn (логистическая регрессия, случайный лес, Extra Trees,
градиентный бустинг). Все модели для каждого дня оценивают вероятность эффекта
мероприятия, из неё получаются даты начала и окончания; качество сравнивается
перекрёстной проверкой по скважинам.

Окружение: Windows, Python 3.12, виртуальное окружение `.venv` в корне проекта.
Запуск из корня проекта:

```bash
python -m gtm_detector.ml_freq compare                      # сравнить все модели
python -m gtm_detector.ml_freq train --model gboost         # обучить и сохранить
python -m gtm_detector.ml_freq predict --model gboost       # найти мероприятия (веса берутся из weights/weights.zip)
python -m gtm_detector.ml_freq pack-weights                 # записать все веса в архив weights.zip
python -m gtm_detector.ml_freq audit                        # отчёт о качестве данных 2020–2026
python -m pytest gtm_detector/ml_freq/tests -q              # тесты
```

По умолчанию модели учатся на 14 исходных полугодовых выгрузках
`resources/statistics/<год>/*.xls` (2020–2026, 616 скважин) и разметке
`resources/labeled_data.xlsx`: в обучение попадает 424 мероприятия на 369 скважинах
(из 786 строк разметки; 313 отброшены, потому что подъём частоты не виден у даты
начала; ещё 49 — 40 дубликатов, 5 скважин без телеметрии частоты, 3 строки без
увеличения частоты и 1 невыполненное).
Сдвига на 180 дней в этих файлах нет (он был в прежнем склеенном файле и исправляется
только при его чтении). Лучший результат у градиентного бустинга: найдено 74 %
размеченных мероприятий, дата начала ±3 дня — 89 %. Детектор на правилах
(ветка `feature/increase-f-gtm`) пока не превзойдён. Подробности, таблицы до и после
и оговорки о сравнимости метрик — в `gtm_detector/ml_freq/README.md`.

Эксперименты с окном отбора разметки (поиск подъёма частоты до 14 дней раньше даты
технолога, начало метки по дню скачка частоты) лежат в ветке
`feature/widen-label-window` и в `main` не влиты. На градиентном бустинге они не дали
значимого улучшения, а сдвиг начала метки ухудшил точность даты начала.

Подробности и результаты - в `gtm_detector/ml_freq/README.md`. Разбор каждого класса,
функции и метода с примерами из проекта — в `gtm_detector/ml_freq/Построчный_разбор_ml_freq.pdf`
(собирается из кода: `python -X utf8 docs/ml_freq_walkthrough/build.py`).

Отладка в VS Code: готовые конфигурации для `audit`, `compare`, `train`, `predict` и тестов —
в `.vscode/launch.json` (вкладка Run and Debug, F5).

Документацию ведёт агент Claude Code `docs-maintainer` (`.claude/agents/`): после каждого
ответа с изменениями в проекте его вызывает Stop-хук `.claude/hooks/docs_sync.py`.
Все агенты проекта описаны в `docs/CLAUDE_AGENTS.md`.

# dirs

`gtm_detector/ml_freq` (активная разработка): детектор на машинном обучении — данные,
признаки, модели, оценка, командная строка, тесты и веса (`weights/weights.zip`).

`helpers`:
- `time.py`: статичный класс для работы со временем; создаёт папки по датам

`main.py`: запуск прежней нейросети. Он импортирует модули `gtm_detector.data`,
`gtm_detector.pipeline` и другие, которых в нынешнем `gtm_detector` нет (остался только
`ml_freq`), поэтому без правок не запускается.

`docs`:
- `ml_freq_walkthrough/`: генератор PDF «Построчный разбор ml_freq» (`build.py`) и
  пояснения к каждому объекту кода (`explanations/`)
- `CLAUDE_AGENTS.md`: описание агентов Claude Code этого проекта

`.claude`: агенты (`agents/`) и Stop-хук обновления документации (`hooks/`, `settings.json`).
`.vscode`: конфигурации запуска и отладки (`launch.json`).
`CLAUDE.md`: память проекта для Claude Code (задача, команды, стиль, правила обучения, данные).
`pyproject.toml`: настройки `ruff` (PEP 8, длина строки 99). `req.txt`: версии библиотек.

`resources` (только чтение, папка скрыта от Git):
- `statistics/<год>/*.xls`: исходные полугодовые выгрузки замеров (20–26 годы, 14 файлов)
- `labeled_data.xlsx`: разметка технологов (786 строк).

`results`: 
- `ml_freq/`: отчёты команд `compare`, `predict` и `audit` (создаются автоматически),
  описание папки — в `results/ml_freq/README.md`.
