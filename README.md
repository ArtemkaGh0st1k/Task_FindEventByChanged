---
Проект создан для решения задад детекции начала `ГТМ`
и конца `ГТМ`.

В ходе было реализовано два подхода:

1) Попытка дотянутся до сайта `deepseek` и скормить ему 
некий промпт, который содержал последовательную инструкцию,
дополнительную информацию и необходимые данные.
Далее после запроса мы должны были спарсить эти данные
в определённый формат.

*Архитектура:*

`constants`:
- `path.py`: хранит класс констр.переменн (url, пути к сохр и тд)

`helpers`:
- `converter.py`: вспомогательный класс для конвертации (не использовал)
- `time.py`: статичный класс для работы со временем; создаёт папки по датам

`models`:
- `base_model.py`: Класс родитель, хранит имя модели, базовый промпт.
- `deepseek.py`: Основной класс для обращения к deepseek-сайту.
- `ollama.py`: Класс для работы с локальной моделью с помощью сервиса `ollama`.

`parsers`:
- `base_parser.py`: Основной класс для парсера ответов. В нем есть парсер 
моделей `deepseek-r1:1.5b`, `llama3.2:1b` и `qwen2.5:0.5b`.
- `deepseek_parser.py`: Класс для парсинга с deepseek сайта.
- `ollama_parser.py`: Класс для парсинга `ollama`.

`resources`:
- `input_dataset.xlsx`: Данные с замеров по скважинам (по добыче нефти,
жидкости, давлений, частоты, состояний скважин)
- `output_dataset.xlsm`: Данные технологов с расставленными датами (26 год).

*Результат:*
- Проблемы размера кеша (после повтороного запуска его 
размер увеличивается). После 20-ого запуска размер
кеша составлял около 1гб.
- Также необходимо один раз авторизоваться и сохранить
эти данные для повтороного захода.
- Проблема с библиотекой `nodriver`: она работает для 
браузера `Google Chrome`, но у меня его нет и скачать проблематично.
Я запускал через `subprocess` через браузер `Microsoft Edge`.
- Попытка развернуть локальную модель через сервис 'ollama', 
отправить промпт и получить ответ. Попробовал с несколькими моделями -
лишь одна выдала ответ и то корявый. Остальные не ответили (возможно 
не хватило мощноси пк).

2) Второй способ - сделать нейронную сеть.
Входной слой - данные замеров технологов.
Выходной слой - результат в виде дат начала и окончания ГТМ.
**Причем берем только ГТМ - увеличение частоты!**

*Архитектура:*

Основная директория - `gtm_detector`.
Результаты в папке `results`.

`gtm_detector`:

`config`:
- `config.py`: Класс `PipelineConfig` - это гиперпараметры для входных данных.
               Класс `GTMVerdict` - резултат нейронки в виде этого класса.

`data`:
- `dto.py`:  Промежуточные классы для хранения данных после обработки.

`data/excel`:
- `base_loader.py`: Класс-родитель, который заставляет реализовать 
методы у классов-наследников. Метод `check_unnamed_columns` ищет столбцы, 
которые помечены `Unnamed` и вычисляет их индексы.
- `config.py`: Конфигурация для импорта входных/выходных данных.
- `in_loader.py`: Один из главных классов, который преобразует
входные данные из excel в dataFrame. 
Главный метод (последний рабочий метод) - `load_wells_by_sheets1`.
- `out_loader.py`: Один из главных классов, который преобразует
выходные данные из excel в DataFrame.
Основной метод - `load_success_and_contain_dates` - выгружает 
информацию о скважинах, которые успешны и имеют даты начала 
и окончания ГТМ.

`feature`:
- `feature_engineering.py`: Класс, в котором происходит работа
с признаками. Для теста нейронка предложила следующие признаки:
1. Сглаживание дебита - берется интервал дебитов и считается медиана.
2. Удельный дебит - удельный приток на 1 гц частоты.
3. Скачок частоты.
4. Частота.
5. Работает/неработате скважина.

`models`:
- `gtm_detector.py`: Основной класс, где происходит логика
работы с нейронкой.

`parsers`:
- `note_paresers.py`: Конвертирует строковые состояние в bool.
Также есть метод для извлечения сторонних комментариев.

`plot`:
- `visualize.py`: Класс для визуализации данных.
В последний раз метод `visualize` реализовывал 
графики, в которых есть:
1. Давление
2. Дебит нефти
3. Дебит жидкости
4. Частота
5. Даты начала и окончания

`results`: 
- `22-09-2026`: Первые результаты, которая выплюнула нейронка.
- `success_and_has_dates.csv`: Файлик с отфильтрованными скважинами (
но не только с `увеличением F`).

- `success_and_has_dates/`
    `all_gtms`: Все виды ГТМ с первоначального файлика Рината,
    которые успешны и имеют обе даты.
    `increase_f_gtm`: Только ГТМ с увеличением F

*Результат:*

- Пока непонятно как работает нейронка.
- Проблема с признаками.
- Пока что мало данных.
- Разобраться с выбором моделей и алгоритмов.
