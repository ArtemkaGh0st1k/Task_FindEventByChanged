# results/ml_freq — результаты ML-детектора «увеличение частоты F»

Здесь лежат отчёты пакета `gtm_detector/ml_freq`. Все файлы создаются командами
(запуск из корня проекта) и пересоздаются при повторном запуске:

| Папка | Команда | Данные |
|-------|---------|--------|
| `data_audit/` | `python -m gtm_detector.ml_freq audit` | объединённые 2021–2026 |
| `comparison_merged/` | `python -m gtm_detector.ml_freq compare --out-dir results/ml_freq/comparison_merged` | объединённые 2021–2026 |
| `predict_gboost_merged/` | `python -m gtm_detector.ml_freq predict --model gboost --out-dir results/ml_freq/predict_gboost_merged` | объединённые 2021–2026 |
| `comparison/` | `compare --dataset test` | тестовые 2026 г. (`resources/test_datas`) |
| `predict_transformer/` | `predict --dataset test --model transformer` | тестовые 2026 г. |

Без `--out-dir` команды `compare` и `predict` создают папку с датой и временем
запуска (`ДД-ММ-ГГГГ_ЧЧ-ММ-СС`).

## `data_audit/` — проверка качества данных 2021–2026

Отвечает на вопрос: что было в исходных файлах, что исправлено и что не взято в
обучение. Подробное обоснование всех решений — в docstring `gtm_detector/ml_freq/audit.py`.

### `data_audit.xlsx` — полный отчёт, четыре листа

- **«сегменты»** — куски файла статистики по датам. Файл склеен макросом из
  отдельных выгрузок, и часть из них записана на 180 дней позже. Для каждого куска:
  даты, сколько скважин, доказательства для сдвига 0 и 180 дней (по разметке
  технологов и по исходной выгрузке 2026 г.), решение — «без сдвига»,
  «сдвиг −180 дн» или «исключён» — и его обоснование.
- **«мероприятия»** — все 786 строк итогового файла технологов. У каждой —
  решение: «принято» или причина отказа (скважины нет в статистике, нет замеров,
  частота не поднялась, дубликат и др.). Принято 135.
- **«скважины»** — все скважины статистики: сколько дней с замерами, доля дней с
  телеметрией частоты, сколько мероприятий принято, статус — используется с
  разметкой, без разметки или не используется (нет телеметрии частоты).
- **«не числа»** — ячейки, где вместо числа текст или дата. Сейчас пусто; лист
  нужен для проверки будущих файлов.

### `data_audit.png` — график

Сколько скважин с замерами было в каждый день: сверху — как в файле, снизу —
после исправления. Голубым подсвечены периоды, сдвинутые на 180 дней назад,
красным — исключённые. Наглядно показывает, что было не так со склейкой.

### `rejected_labels.csv` — список не взятых мероприятий

575 мероприятий, отброшенных по трём главным причинам, с пояснением:

| Причина | Строк |
|---------|-------|
| скважины нет в статистике | 333 |
| нет замеров около даты начала (±14 дней) | 153 |
| частота в замерах не поднялась около даты начала | 89 |

Столбец `строка Excel` — номер строки в `Итоговый_файл_c_2021_2026.xlsx`.
Разделитель `;`, кодировка UTF-8 — открывается в Excel двойным щелчком.
Это часть листа «мероприятия» из `data_audit.xlsx`; файл удобно отдать
технологам: каждая исправленная строка — новый пример для обучения.

### `training_data.xlsx` — данные, на которых учатся модели

Только то, что пошло в обучение: 135 принятых мероприятий на 122 скважинах и замеры
этих скважин **после исправления** (сдвинутые на 180 дней блоки возвращены на место,
исключённые сегменты пустые). Даты — 30.06.2020–03.09.2026.

- **«мероприятия»** — принятая разметка с заголовками итогового файла технологов
  (Куст, Скважина, Тип ГТМ, даты начала и окончания мониторинга, Текущее и Новое
  значение, Причина прекращения мониторинга, Год) плюс `строка Excel` и
  `эффект продолжался` (для таких мероприятий дни после окончания в обучении не участвуют).
- **«Qж (из OIS)», «Обв (из OIS)», «Qн (из OIS)», «Рлин (из OIS)», «Fэцн ТМ(сут)», «Рзаб»** —
  замеры в раскладке исходного файла статистики: строка — скважина (`№ скв.`, `№ куста`),
  столбец — дата `ДД.ММ.ГГГГ`. Пусто — замера нет или ячейка исключена.
- **«разметка по дням»** — что видит модель при обучении: 1 — день эффекта по разметке,
  0 — эффекта нет, пусто — день не участвует в обучении (дальше 45 дней от мероприятий
  или после окончания мероприятия с продолжающимся эффектом).

## `comparison_merged/` — сравнение моделей на данных 2021–2026

Пять моделей (Transformer, логистическая регрессия, случайный лес, Extra Trees,
градиентный бустинг), перекрёстная проверка по скважинам, 5 фолдов:
135 мероприятий на 122 скважинах.

### `comparison.xlsx`

- **«Сравнение»** — по строке на модель: доля найденных размеченных мероприятий
  (recall), точность (precision), F1, точность даты начала и окончания
  (точно / ±1 / ±3 / ±7 дней, средняя ошибка в днях), число найденных / пропущенных /
  лишних, ROC-AUC по дням, время обучения.
- **Лист на каждую модель** (`transformer`, `logreg`, `random_forest`,
  `extra_trees`, `gboost`) — каждое размеченное мероприятие рядом с найденным
  моделью: даты по разметке, даты модели, разница в днях. Пустые даты модели —
  мероприятие не найдено. Столбец «эффект продолжался» — для таких мероприятий
  ошибка окончания не считается. По этим листам видно, где модель ошибается.

### `comparison.png`

Шесть главных метрик графиком, по панели на метрику, в каждой — все модели:
найдено размеченных (recall), начало точно и ±3 дня, конец точно и ±7 дней,
ROC-AUC по дням.

## `predict_gboost_merged/` — поиск мероприятий без разметки

### `events_gboost.xlsx`

Что нашёл градиентный бустинг (обучен на всех 122 скважинах) по одним замерам
2021–2026: 770 мероприятий на 468 скважинах. Столбцы: скважина, куст, начало
эффекта, окончание эффекта, статус («эффект продолжается» — период дошёл до конца
данных скважины, окончание не определено; таких 112).

Так детектор работает на практике. Файл можно отдать технологам на выборочную
проверку: часть «лишних» мероприятий может оказаться настоящими, которых просто
нет в разметке, — только так можно узнать реальную точность.
